# Подготовка и обновление кэша моделей

## Кэш в браузере

Подготовленный `manifest.json` должен переноситься на сервер вместе с ресурсами.
Перед созданием портрета `/api/model-versions/<displayID>` возвращает небольшой
список его зависимостей и SHA-256 фактически выдаваемых файлов. Этот список
всегда проверяется на актуальность (`no-cache`, ETag); общий многомегабайтный
манифест браузеру не отправляется.

Просмотрщик запрашивает геометрию, текстуры, анимации, метаданные, JS и CSS с
`?v=<sha256>`. Такие ответы получают `max-age=31536000, immutable`: обычное
обновление страницы повторно их не скачивает. Хеш учитывает облегчённую модель
или исходный fallback, а для просмотрщика — применённые адаптеры. Изменение
одного файла меняет только его адрес. Обновление настроек камеры не сбрасывает
кэш моделей: настройки по-прежнему запрашиваются отдельно.

Запрос без хеша перепроверяется через ETag. Несовпадающий хеш получает `410`
с `no-store`, чтобы под старым неизменяемым URL никогда не оказались новые байты.
Браузер может удалить свой кэш самостоятельно или по запросу пользователя.

При обновлении зависимостей продолжайте обычную подготовку и перенос кэша ниже;
хеши вычисляются автоматически, вручную повышать номер версии не нужно.
Проверки `node web/voice-vote/tests/model-cache-browser.mjs` и
`node web/voice-vote/tests/model-cache-render.mjs` проверяют повторное использование
ресурсов и обновление адресов. Первая входит в обязательную сборку Docker;
вторая использует локальный подготовленный кэш и настоящие портреты в WebGL.

Все команды ниже выполняются в PowerShell из корня репозитория
`C:\Projects\wow-addons\WowVoice`. Java-сервер и сайт запускать не нужно:
скрипт поднимает временный локальный сервер и невидимый Firefox, затем закрывает их.
Он не проигрывает аудио и не отправляет голоса.

## 1. Один раз установить инструменты

Нужен Node.js. Установите зависимости проекта и браузер для подготовки:

```powershell
npm.cmd ci
npm.cmd ci --prefix web/voice-vote
Push-Location web/voice-vote
npx.cmd playwright install firefox
Pop-Location
```

После обновления версии Playwright повторите установку Firefox.
Сборка кэша выполняется на компьютере с доступом к `wow.zamimg.com`.

## 2. Подготовить актуальный каталог заданий

Сначала обновите установленные библиотеки и импортированные данные проекта
по скиллу [update-libraries](../../.agents/skills/update-libraries/SKILL.md),
если библиотеки менялись. Путь к установленным библиотекам берётся из
`config/build.env.local.ps1`.

```powershell
node web/voice-vote/export-site.mjs artifacts/voice-vote-deploy/catalogue
if ($LASTEXITCODE -ne 0) { throw 'Catalogue export failed' }
```

При неизменной базе и уже подготовленном каталоге этот шаг можно пропустить.
Кэш строится по `site-catalogue.json`, а не по фиксированному списку NPC.

## 3. Скачать недостающие модели

```powershell
node web/voice-vote/prepare-model-cache.mjs
if ($LASTEXITCODE -ne 0) { throw 'Inspect prepare-report.json and rerun preparation' }
```

Скрипт объединяет задания с одинаковым `displayID`, открывает каждый уникальный
облик в настоящем просмотрщике и проверяет текстуры, камеру, свет, разговор
и возврат в неподвижную позу. По умолчанию облики обрабатываются последовательно;
ошибочная модель получает ещё две попытки. Общие файлы используются повторно.

Результат находится в `artifacts/voice-vote-model-cache/`:

- `modelviewer/` — файлы моделей, текстуры, просмотрщик и его CSS;
- `manifest.json` — готовые облики, список зависимостей и SHA-256 файлов;
- `prepare-report.json` — итог прохода и ошибки с ID затронутых заданий.

Папка исключена из Git. OGG туда не копируются. Не запускайте два экземпляра
подготовки одновременно в одну папку. Ctrl+C завершает работу после текущего
облика; затем можно повторить ту же команду. Успешные результаты сохраняются
после каждого облика. Строка `reused` означает, что файлы сверены с манифестом
и повторная загрузка не нужна.

## 4. Проверить работу без Wowhead

```powershell
node web/voice-vote/prepare-model-cache.mjs --verify
if ($LASTEXITCODE -ne 0) { throw 'Cache is incomplete: inspect verify-report.json' }
```

На этом проходе серверу запрещено скачивать отсутствующие файлы, а браузеру —
обращаться к внешним доменам. Все облики открываются заново с пустым браузерным
кэшем. Результат — `verify-report.json`.

Готовый полный проход: `completed: true`, `partial: false`, `ready` равно `total`,
`failures` пуст. Задания без известного облика отдельно перечислены в
`unavailableQuestIDs`: для них сайт штатно показывает свиток, они не считаются
ошибкой скачивания. Если ошибки остаются, не считайте кэш полным: проверьте
указанные NPC/ресурсы, повторите подготовку, затем проверку.

## 5. Упаковать и перенести на хостинг

Только после успешного полного прохода шага 4:

```powershell
tar -czf artifacts/voice-vote-deploy/models.tar.gz -C artifacts/voice-vote-model-cache modelviewer manifest.json verify-report.json
if ($LASTEXITCODE -ne 0) { throw 'Cache archive failed' }
```

Передайте `models.tar.gz` на сервер, например в `/srv/talkinghead/import/`.
Из каталога с настроенным `compose.yaml` и `.env` выполните в Linux:

```sh
docker compose stop web
docker compose run --rm --no-deps --user 0 --volume /srv/talkinghead/import:/import:ro --entrypoint sh web -c 'tar -xzf /import/models.tar.gz -C /cache && chown -R 1000:1000 /cache'
```

При ошибке распаковки сначала устраните её. Установите в `.env`
`VOICE_VOTE_MODEL_OFFLINE=true` и запустите:

```sh
docker compose up -d --no-build --wait --wait-timeout 180
```

Нужна актуальная версия web-образа и Compose с поддержкой этой переменной.
Кэш остаётся в постоянном томе `model_cache` при замене контейнера.
Не выполняйте `down --volumes` на рабочем сайте. При недостающем файле в автономном
режиме портрет останется свитком; скрытой загрузки с Wowhead не будет.

## При расширении базы заданий

Повторите шаги **2 → 3 → 4 → 5**, используя прежнюю папку кэша. Новые `displayID`
будут найдены автоматически. Новый квест со знакомым обликом не требует отдельной
копии модели. Отсутствующие файлы догружаются; старые автоматически не удаляются.
Изменение наших настроек камеры или адаптера просмотрщика вызывает повторную
проверку обликов с использованием уже скачанных файлов.

На хостинге сначала установите дополненный кэш, затем согласованно обновите
каталог и внешние аудиобиблиотеки и перезапустите приложения. Новые задания
не должны появляться раньше подготовленных для них моделей.

После обновления исходного кэша также пересоберите и проверьте
[облегчённые файлы портретов](PORTRAIT-PACKS.md):
`npm.cmd --prefix web/voice-vote run test:portrait-packs`, затем
`node web/voice-vote/install-portrait-packs.mjs`.
Каталог `portrait-packs-v1` переносится вместе с `modelviewer`.
При несовпадении хешей сайт автоматически использует исходную модель.

Изменение внешней модели под прежним URL само по себе не обнаруживается:
SHA-256 проверяет локальную целостность, а не наличие обновления у Wowhead.
Для намеренного обновления ресурсов подготовьте отдельную папку и проверьте её:

```powershell
node web/voice-vote/prepare-model-cache.mjs --cache artifacts/voice-vote-model-cache-next
node web/voice-vote/prepare-model-cache.mjs --cache artifacts/voice-vote-model-cache-next --verify
```

Это также потребует проверки совместимости нашего адаптера с новой версией
просмотрщика. Рабочий кэш сохраняется до успешной проверки нового.

## Результат первого полного обхода

Первый полный обход 12.10.2026: 1 270 из 1 271 обликов прошли подготовку
и проверку без Wowhead. Для задания 97290 (NPC 271613, облик 146706,
модель 353152, «Недоделанное поганище») файл не содержит камер. Ресурсы
скачаны, но настройка портрета завершается ошибкой; в игре пользователь также
подтвердил некорректный ракурс. Это требует отдельного исправления камеры,
а не повторного скачивания. Ошибка остаётся в отчёте и не маскируется успешным
результатом. Снимок кэша занял 789 МиБ; это не прогноз размера будущих обновлений.

## Короткая проверка инструментов

```powershell
node web/voice-vote/prepare-model-cache.mjs --quest-ids 7,179,3741
node web/voice-vote/prepare-model-cache.mjs --quest-ids 7,179,3741 --verify
```

Эти команды проверяют только три задания. Их отчёт помечен `partial: true`
и не подтверждает готовность всего каталога. Полный проход запускается без
`--quest-ids`. Дополнительные параметры: `--timeout 60000` (на облик, мс),
`--retries 2`, `--catalogue <путь к site-catalogue.json>`, `--cache <папка>`.
Для ускорения на компьютере с запасом памяти можно добавить `--workers 3`
к подготовке и проверке: до трёх портретов будут обрабатываться одновременно.
Допустимо 1–4, общие загрузки объединяются внутри одного процесса.
