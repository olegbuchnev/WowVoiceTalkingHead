# Локальный прототип сравнения озвучек

Для размещения всего сайта подготовлены два Docker-образа и общий Compose:
[инструкция запуска](DOCKER.md). Java API доступен через общий адрес сайта.

Перед публикацией подготовьте [кэш моделей](MODEL-CACHE.md): там приведены команды
первоначальной загрузки, автономной проверки и расширения при добавлении заданий.

React + Vite и [Java-сервер голосования](../../server/voice-vote/README.md),
отдельные приложения в репозитории TalkingHead Ru. Нужны Node.js и JDK 25+.
Java API использует переносимый каталог метаданных без путей к библиотекам.
Установленные библиотеки нужны для подготовки каталога и локального проигрывателя;
сам сервер голосования можно запустить с JAR и каталогом на другом компьютере.

Из корня проекта:

```powershell
.\voice-vote.cmd
```

Откройте **http://127.0.0.1:5174/** в Firefox. Скрипт при необходимости
устанавливает зависимости через `npm ci`, собирает Java через Maven Wrapper
и запускает оба сервера на loopback
в фоне. Если сервер уже запущен, повторно используется тот же адрес.
Скрипт выводит PID и команду остановки созданного процесса.
Логи находятся в `artifacts/voice-vote-preview/`.

Для разработки клиента с остановкой по Ctrl+C (Java API уже должен работать):

```powershell
cd web/voice-vote
npm ci
npm run dev
```

## Что работает

- Общая громкость всех записей: вертикальный ползунок слева от говорящей головы,
  на узком экране — горизонтальный под ней. По умолчанию 100%; выбранное значение
  сохраняется на год в cookie `thru_vote_volume` этого браузера. Переключение
  вариантов, новая серия и обновление страницы не сбрасывают громкость.
  Кнопка динамика выключает звук и возвращает последнюю ненулевую громкость;
  она хранится в cookie `thru_vote_previous_volume`, в том числе после перезагрузки.
  Колёсико над панелью меняет громкость с шагом 5%, не прокручивая страницу;
  Ctrl/Command с колёсиком остаётся доступным для масштабирования браузера.
- При открытии страницы сначала показывается короткое приветствие и кнопка
  «Начать сравнение». Шапка общая с экраном голосования. Каталог и первые
  портреты загружаются заранее; переход сохраняет готовые модели и не запускает
  звук. Скрытые элементы сравнения недоступны для мыши и клавиатуры. После
  обновления страницы приветствие появляется снова, сохранённые оценки остаются.
- Все описания заданий, доступные хотя бы в двух разных библиотеках. На 12.10.2026:
  3 576 сравнений (1 521 с двумя озвучками, 2 055 с тремя). Несколько пакетов
  Wayfarer считаются одной библиотекой. Для обращений к игроку выбирается общий
  либо мужской вариант текста и записи; это не пол говорящего NPC.
- Данные квестгивера берутся из общей `src/Speakers.lua`: ID, имя, облик, раса и пол.
  Неизвестные значения не угадываются. Задания от предметов/объектов и с несколькими
  возможными квестгиверами тоже доступны для сравнения; вместо неизвестного портрета
  остаётся свиток. Такие голоса сохраняются по квесту, а неизвестная демография — как `null`.
- Переносимый каталог: `data/voice-vote/catalogue.json`; перечень пробелов и счётчики:
  `data/voice-vote/catalogue.coverage.json`. Пересборка из корня:
  `node web/voice-vote/export-vote-catalogue.mjs`. API читает обновлённый каталог;
  после пересборки перезапустите Vite. Три исходных квеста остаются только тестовой выборкой.
- Реальные записи WowVoice, CatQuest и Wayfarer; доступны только установленные
  файлы с SHA-256, совпадающим с текущими манифестами проекта.
  Хеш также проверяется при выдаче аудио: обновление файла после запуска страницы
  не подменит прослушиваемую запись под старым идентификатором.
- Случайный порядок вариантов А/Б/В. Выбор после запуска хотя бы двух записей;
  следующий квест и порядок его вариантов резервируются заранее. Серия содержит
  до пяти неоценённых квестов, без дополнения повторами; над головой виден счётчик.
  Кнопки «Пропустить» нет: переход выполняется после выбора голоса.
  Сервер составляет очередь по cookie: сначала неоценённые пользователем
  сравнения. Среди них первыми идут известные группы раса–пол без допустимых
  голосов, затем остальные. Внутри уровня сохраняется разнообразие групп с
  мягким снижением частоты недавних повторов; внутри группы первыми идут
  сравнения с меньшим числом голосов за текущие файлы. Равные перемешиваются.
  Старые файлы учитываются для наличия голосов у группы, но не для покрытия
  текущего сравнения. Новые и обновлённые записи равноправны; смена только
  номера библиотеки не меняет приоритет.
  Приоритеты загружаются перед первой предзагрузкой и обновляются перед новой серией,
  не заменяя уже подготовленный следующий портрет. При недоступной истории
  показано предупреждение о возможных повторах.
- Предзагрузка одного следующего портрета: скрытый просмотрщик того же размера
  загружает модель и текстуры, применяет камеру и свет, готовит первый кадр Stand.
  При переходе сохраняется тот же экземпляр WebGL; предыдущий уничтожается,
  а в резерве готовится новый. Одновременно смонтированы только два портрета.
  На экране завершения серии заранее резервируется следующая серия и загружается
  её первый портрет вместе с камерой и освещением. Кнопка «Сравнить ещё» использует
  этот же просмотрщик без повторной загрузки или перестановки вариантов.
  Если все задания уже оценены, повторная серия начинается только по нажатию.
  Текст и данные вариантов уже получены в каталоге. Предзагрузка не запускает
  звук; если модель ещё загружается или недоступна, остаётся заглушка со свитком.
  Крупные модели могут загружаться дольше 40 секунд при пустом браузерном кэше.
  Проверка готовности продолжается и после мягкого тайм-аута: поздно загруженная
  модель автоматически заменяет свиток. Бинарные файлы моделей передаются со
  сжатием gzip, когда браузер его поддерживает; качество модели не меняется.
- Каталог проверяется перед переходом дальше, при подготовке новой серии,
  возвращении во вкладку и раз в минуту в видимой вкладке. ETag позволяет получать
  короткий ответ 304, когда данные не изменились. Обновляются только ещё не
  показанные сравнения; текущая запись, позиция в серии и личный чарт сохраняются.
  Страница не перезагружается, приветствие не появляется повторно. Если сервер
  отклонил голос за устаревшие записи (404/409), пользователь видит обычное
  подтверждение выбора, но в общую статистику этот голос не попадает. Каталог
  обновляется в фоне; отклонённый голос не переносится на новые записи.
  Проверка этого сценария: `node web/voice-vote/tests/catalogue-refresh-browser.mjs`.
- Одна 3D-модель в панели с оригинальной текстурой TalkingHeads; `EmoteTalk`
  во время воспроизведения и неподвижный первый кадр `Stand` до запуска и
  после остановки/окончания. Без lip-sync.
- Переключение источника останавливает предыдущий звук. Смена NPC также
  прекращает воспроизведение. Автозапуска звука при открытии страницы нет.
- Каждый выбор сразу отправляется в Java API и сохраняется в SQLite вместе
  с NPC, моделью, расой, полом и версиями/хешами предложенных записей.
  Новая история в localStorage не накапливается. Старые проверяемые оценки
  переносятся автоматически и удаляются из браузера после подтверждения сервера.
  Пользователь определяется случайной HttpOnly cookie без регистрации.
  Интерфейс подтверждает выбор сразу; сервер принимает голос в постоянную очередь
  и записывает в SQLite фоновым обработчиком. Открытая страница незаметно повторяет
  временно неудавшуюся отправку, без сохранения новой очереди в localStorage.
  Состояние серверной очереди и ошибки видны в админке. Повторная оценка того же
  сравнения заменяет прежнюю.
- После выбора на месте говорящей головы показывается название выбранной
  библиотеки и кнопка «Следующая реплика». До перехода повторный голос исключён.
  Диаграмма «Ваши предпочтения» суммирует личные выборы WowVoice, CatQuest и
  всех модулей Wayfarer, показывает количество и процент на всём этапе голосования.
  Учитываются выборы текущей сессии сразу после нажатия; повтор заменяет выбор.
  F5 возвращает приветствие и обнуляет чарт, сохраняя cookie и оценки на сервере.
- После последнего подтверждённого выбора заголовок меняется на «Готово!».
  Область «Вы выбрали» с цветным названием библиотеки остаётся на прежнем месте,
  кнопка «Следующая реплика» скрывается. Фраза завершения и кнопка следующей серии
  занимают место карточек; чарт не сдвигается. Если неоценённых
  квестов нет, повторный просмотр запускается только кнопкой «Сравнить повторно».
  24 фразы завершения находятся в `src/completion-messages.js`: случайный порядок,
  без повторов в пределах сессии до исчерпания всех фраз. Чарт между сериями сохраняется.
- Цвета диаграммы соответствуют каталогу аддона (`src/VoiceComparison.lua`):
  WowVoice — голубой, CatQuest — оранжевый, Wayfarer — зелёный.
- Разрешение 3D-холста учитывает экранный размер портрета и devicePixelRatio;
  рендер выполняется с двукратным запасом по каждой оси для сглаживания
  (максимум 1024 × 1024). Масштабирование браузера и смена экрана обновляют
  разрешение, не меняя логический размер портрета 115 × 115.

## Данные и ограничения

Путь к библиотекам читается из `config/build.env.local.ps1` (литеральное
присваивание `WOWVOICE_FOREVER_BETA_ADDONS` в одинарных кавычках) или переменной
окружения. Локальный конфиг имеет приоритет. Нужны зависимости корневого
проекта (`npm ci` из корня), так как сервер использует общий разбор Lua-таблиц.
Сторонний Lua не исполняется. Аудио раздаётся по разрешённым ID напрямую из
установленных библиотек, с поддержкой Range; оно не копируется и не кэшируется
в проекте. Каталог формируется при первом запросе; после изменения библиотек
нужно обновить метаданные и перезапустить сервер.

Текст берётся из общей QuestTexts; это не точные субтитры каждой библиотеки.
Прокрутка повторяет алгоритм `src/Portrait.lua`: неподвижные блоки текста,
перекрытие в две строки, плавные переходы до 0,65 секунды. Время переходов
оценивается по длине слов, паузам пунктуации и длительности записи; переносы
измеряются браузером после загрузки шрифтов. План пересчитывается при смене
записи или размера текста. Все примеры используют общее
или мужское обращение к игроку; пол говорящего берётся отдельно из Speakers.

Модели, внешность NPC, экипировка и текстуры загружаются с
`wow.zamimg.com/modelviewer/classicplus/` — это источник страницы Wowhead Forever
(окружение 16), а не Classic Era и не Retail. Одинаковый displayID в разных
окружениях может означать разную внешность: у Стена 1362, но в Retail другая
экипировка. Проверенный движок просмотра пока берётся отдельно из
`modelviewer/live/viewer/viewer.min.js`; все модельные данные он читает из
`classicplus`, без подстановки Retail при ошибке. Запросы идут через локальный
сервер с фиксированным upstream. Первый просмотр требует Интернета.
Модельные ресурсы сохраняются только в исключённом из Git каталоге
`artifacts/voice-vote-model-cache/`, отдельно по окружениям. Используются
displayID 1362, 221 и 1859 из нашей базы.
Проверка трёх примеров не подтверждает поддержку всех моделей Forever.
При сетевой ошибке отображается
сообщение о недоступности модели.

Камера и освещение согласованы пользователем 2026-10-12: визуальный результат
очень близок к игре. Текущие настройки приняты как базовые для прототипа:
общие игровые профили камеры, калибровка ребёнка по измерению из клиента,
измеренный свет Стена и поправка гаммы 2.2 в веб-просмотрщике. Дальнейшие
изменения сверять с этим результатом; согласование относится к просмотренным
примерам и не означает проверки всех моделей Forever.

Камера сайта использует общие `src/CameraModels.lua` и `src/CameraProfiles.lua`.
Локальный сервер выполняет только эти два собственных модуля через Fengari и
вызывает `GetPortraitCameraProfile`: приоритеты и индивидуальные исключения
не дублируются в JavaScript. Выбор идёт по FileDataID загруженной модели:
878772 → dwarf, 124495 → model:124495, 1011653 → human_male. Изменения файлов
профилей подхватываются при следующем запросе камеры; отдельный импорт не нужен.
В локальном режиме `npm run dev` Vite следит за обоими Lua-файлами: после
сохранения открытый портрет автоматически пересоздаётся с актуальным профилем,
показывая свиток на время подготовки. Страница, воспроизведение аудио и выбор
пользователя сохраняются. Файлы в `src/` — единственный источник этих настроек;
изменения отдельной установленной копии в папке игры сайт не отслеживает.
Для будущего размещения сайта эти же файлы должны поставляться с сервером
из той же версии репозитория; локальный механизм Vite относится к прототипу.

База ракурса берётся из камеры типа 0 внутри M2 Forever, а не из автоматического
охвата всего тела. API `/api/portrait-camera/<FileDataID>` возвращает профиль и
первую позу камеры. Парсер поддерживает MD20/MD21 версий 272 и 274; учитывает
первый ключ положения, цели, наклона и FOV. Для модели без портретной камеры или
с неподдерживаемым форматом показывается недоступность модели, без незаметной
подстановки произвольного ракурса. Камера не анимируется вместе с разговором.
Поправки применяются через преобразование модели просмотрщика; ракурс
сохраняется при остановке, смене разрешения и загрузке экипировки.

Это первый адаптер камеры, а не подтверждённая копия алгоритма PlayerModel.
Ракурс Стена подтверждён пользователем. Для SD-ребёнка 124495 получено измерение
из клиента: `native-camera-samples.json` хранит исходные eye/target/position,
worldScale 0.39378321170807 и масштаб модели 1 при distanceScale 1.5.
В этом измерении `nativePoint = authoredPoint * worldScale - position *
(1 - worldScale)`, поэтому поправки профиля переводятся в M2-единицы с множителем
`1 / worldScale - 1` ≈ 1.539468. Числа eye/target воспроизводятся с погрешностью
менее 0.000001; визуальное совпадение в движении ещё требует проверки в игре.
Это калибровка по конкретному измерению, а не доказанная универсальная формула:
на остальные модели она не распространяется. Изменение исходной M2-камеры или
приближения аннулирует калибровку до нового измерения. Общие игровые профили
остаются единственным источником поправок distance/y/z.
Окно модели прямоугольное, как в аддоне; прежняя круглая CSS-маска удалена.
До готовности модели, текстур и камеры показывается игровой свиток
`INV_Misc_Note_01`: 64×64 по центру портрета без дополнительной рамки,
как в `src/Portrait.lua`. Модель открывается после отрисовки настроенного
ракурса; при ошибке остаётся свиток. При смене NPC заглушка появляется заново.

Время воспроизведения и длительности на карточках скрыты. Жёлтая полоса
прогресса обновляется через `requestAnimationFrame` по часам аудио, без
перерисовки всей страницы и задержки CSS-перехода.

Свет хранится отдельно в `src/native-portrait-light.json`: это значения
`TalkingHeadRu.Model:GetLight()`, присланные пользователем для Стена. Рассеянный
свет RGB ≈ (0.698, 0.698, 0.698), направленный RGB ≈ (0.8, 0.8, 0.639), обе
интенсивности 1, point (0, 1, 0), omnidirectional false. Адаптер
`src/portrait-light.js` переводит направление лучей в вектор к источнику в
координатах камеры и отключает два дополнительных источника Wowhead. Пока
используется один измеренный свет для всех трёх NPC; отдельные параметры
по расам не добавлены. Настройки камеры и общие игровые профили не меняются.

`viewer-lighting.mjs` локально адаптирует GLSL/WGSL просмотрщика: убирает верхнее
ограничение суммы освещения до умножения на текстуру, сохраняя ограничение
конечного цвета. Иначе сумма измеренных ambient + diffuse до ≈ 1.498 теряется.
Коэффициент света применяется с поправкой гаммы 2.2: текстуры просмотрщика
уже кодируют экранный цвет, и прямое умножение давало слишком резкие светлые
участки на коже. Поправка смягчает этот эффект, сохраняя измеренные параметры
источника. Это приближение линейного освещения; точная цветовая обработка WoW
не воспроизводится. Свечение и эффекты материалов не отключаются: проверка
на Стене показала, что их отключение не устраняет этот эффект.
Оригинал в кэше остаётся нетронутым; при изменении ожидаемых участков шейдера
сервер выдаёт ошибку вместо молчаливого применения неверной замены. Это адаптация
веб-рендера по измерению и снимку, а не гарантия полного совпадения шейдеров WoW.
Свет и компиляция изменённого шейдера проверяются в Firefox/WebGL2 вместе с
анимациями. После изменения адаптера нужна полная перезагрузка страницы.

Шрифты русского клиента извлечены из установленного Forever 1.60.1.70338:
`MORPHEUS_CYR.TTF` для имени (QuestTitleFont, 18 px), `FRIZQT___CYR.TTF`
для текста (QuestFont, 13 px) и интерфейса (GameFontNormal, 12 px;
Small, 10 px; Large, 16 px). Файлы находятся в `public/fonts/`, Google Fonts
не используются. В интерфейсе сайта размеры увеличены отдельно для читаемости:
подписи 16 px, выбор голоса 18 px, воспроизведение 20 px.
Карточки на узком экране располагаются столбцом без уменьшения шрифтов.
Интерфейс вне говорящей головы использует игровой Friz — тот же шрифт,
что был на исходных карточках вариантов: заголовок, бренд, кнопки, подсказки,
статистика и подтверждение выбора. Source Sans 3 остаётся локальным резервом
для отсутствующих символов; его файл и лицензия OFL находятся в `public/fonts/`.
Единственное исключение — кнопка CurseForge: её шрифт и оформление совпадают
с GitHub Pages (`Segoe UI` на Windows).
Остальные элементы не зависят от системного шрифта или доступности Google Fonts;
игровые шрифты внутри говорящей головы сохранены.
Определения игровых шрифтов сверены с
[Fonts.xml](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_Fonts_Shared/Shared/Fonts.xml)
и [FontStyles.xml](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_Fonts_Shared/Shared/FontStyles.xml).

Логическая геометрия панели взята из `src/Portrait.lua` при масштабе головы 1:
570 × 155, модель 115 × 115 с отступами (21, 21), рамка 145 × 145,
имя в (152, 25), текст шириной 376 единиц, правый отступ 42,
полоса прогресса 542 × 2. Игровые единицы не равны экранным пикселям:
на результат влияют разрешение и масштаб интерфейса игры, а в браузере —
масштаб страницы и плотность пикселей. По предоставленным скриншотам
вся панель увеличена в 1,625 раза (`--head-screen-scale` в `style.css`),
до 926,25 × 251,875 CSS-пикселей. Вместе с ней пропорционально увеличиваются
шрифты, модель, текстура и отступы. Это настройка под игровой скриншот,
а не универсальный коэффициент WoW для любого монитора. Сглаживание шрифта
зависит от браузера. На узком экране панель прокручивается горизонтально, её
геометрия и шрифты не уменьшаются. Кнопки закрытия внутри фрейма нет;
реплику можно остановить кнопкой выбранного варианта озвучки.

Правый отступ сверён непосредственно с установленным retail 12.1.0.69933:
`Interface/AddOns/Blizzard_FrameXML/TalkingHeadUI.xml` (FileDataID 5612662),
у имени `RIGHT x="-42"`, у текста `BOTTOMRIGHT x="-42"`. В аддоне и на сайте
сохранено это значение, включая версию сайта без крестика. Межстрочный шаг
описания на сайте — 13 логических единиц, как у нашего QuestFont; на паре
предоставленных скриншотов шаг строк составляет около 32 экранных пикселей
в игре и 31–32 на сайте. В самой retail-панели используется другой шрифт
(`GameFontHighlightLarge` с автоматическим уменьшением), поэтому его размер
не переносится вместо выбранного в аддоне QuestFont.

Публичной публикации нет; сервер голосования пока работает локально. Vite build проверяет клиентскую
сборку, но `dist` без локального API и установленных библиотек недостаточен для
работы. Приложение и его зависимости не входят в ZIP аддона и не изменяют
основной сайт. Настройка публичного размещения аудио/моделей — отдельный этап.

## Проверки

Из этой папки:

```powershell
# Один раз после установки/обновления Playwright:
npx playwright install firefox
npm test
npm run build
# Отдельно быстрый браузерный регрессионный тест загрузки портретов:
npm run test:portraits
# После сборки Java JAR и установки Firefox для Playwright:
npm run test:browser
npm run test:batches
npm run test:full
```

`npm test` проверяет Range, реальные записи установленных библиотек и запускает
браузерную проверку медленной загрузки портретов. `test:unit` запускает только
модульные тесты. `test:portraits` работает без Java, библиотек и кэша Wowhead:
реальный React-интерфейс получает управляемую заглушку внешнего 3D-движка.
Виртуальное время проверяет задержки 41 и 131 секунду за несколько секунд:
свиток исчезает после готовности модели и камеры, включая восстановление после
тайм-аута; серия не сбрасывается. Это проверка жизненного цикла интерфейса,
а не качества конкретных M2. Реальные модели проверяются по [MODEL-CACHE.md](MODEL-CACHE.md).

`test:audio` проверяет предзагрузку всех вариантов текущего и следующего
сравнения ещё на приветственном экране, а также первого сравнения новой серии
до нажатия «Сравнить ещё». Firefox воспроизводит синтетический звук из памяти:
повторных запросов за уже загруженными записями быть не должно. Предзагрузка
хранит только текущие и ближайшие записи; старые освобождаются. Раннее нажатие
до завершения загрузки запускает обычное потоковое воспроизведение.
Тест входит в `npm test` и обязателен при сборке каждого Docker-образа сайта:
ошибка останавливает сборку. Браузер остаётся только в сборочном слое.

Сборка `web/voice-vote/Dockerfile` дополнительно запускает настоящий Nginx с
боевой конфигурацией и синтетическим бинарным файлом: проверяет gzip, уменьшение
объёма, точное восстановление байтов, заголовок Vary и ответ без сжатия, когда
клиент его не поддерживает. Отключение сжатия моделей прерывает сборку образа.
Тестовые данные и скрипт проверки не попадают в итоговый образ.
Workflow [voice-vote-tests.yml](../../.github/workflows/voice-vote-tests.yml)
выполняет переносимые тесты портретов и сборку образа при изменениях сайта.

`test:full` проверяет весь каталог через Java API с временной базой, голосование
без известного NPC и выравнивание двух карточек слева с пустой третьей колонкой.
Браузерный тест использует Firefox, загружает все три 3D-модели, проверяет
переключение Talk/Stand, аудио, отправку оценок в Java API, повтор после ошибки, следующий NPC и
мобильную раскладку. Звук автоматического теста приглушён. Снимки сохраняются
в `artifacts/voice-vote-preview/`. Тест сам запускает Java/Vite с отдельной
временной базой и случайными портами. Если Firefox Playwright ещё не установлен:
`npx playwright install firefox`.

Оформление: Blizzard TalkingHeads из существующего аддона, см.
[`public/NOTICE.txt`](public/NOTICE.txt). Интеграция просмотрщика основана на
публичном примере [wow-model-viewer](https://github.com/Miorey/wow-model-viewer);
сам ZamModelViewer читается с сервера Wowhead, не добавляется в Git.

Сброс неподвижной позы в `src/model.js` использует адаптер внутренних методов
кэшированного ZamModelViewer: сброс времени/смешивания и пересчёт костей
с нулевым шагом перед паузой. При обновлении просмотрщика запускать
`npm run test:browser`: он сравнивает изображение после остановки и окончания
записи с исходной позой каждого персонажа, а также проверяет возврат EmoteTalk.
