# Подготовка релиза TalkingHead Ru для CurseForge

Работай из корня текущей копии репозитория. Правила сборки находятся в
`BUILD.local.md` (раздел `PackageAddon`) и `docs/DEVELOPMENT.md`
(разделы `Build release package` и `GitHub publication`).

## Версия и архив

- Определи версию по `src/TalkingHeadRu*.toc`; во всех TOC она должна совпадать.
  Используй соответствующий блок «Что нового» в `README.md` и согласованные
  пользователем изменения. Подготовка для CurseForge уже выпущенной версии
  не требует нового номера, тега или повторного GitHub-релиза.
- Готовый ZIP находится в `artifacts/WoWVoice/TalkingHeadRu-<version>.zip`.
  Если архив этого выпуска уже собран и проверен, используй его. Если архив
  отсутствует или исходники изменились, выполни проверки и `PackageAddon`
  по документации сборки. Запрос только ченджлога не требует пересборки ZIP.
- В архиве должна быть одна корневая папка `TalkingHeadRu/`, актуальная версия
  во всех TOC и только файлы аддона. Внешние библиотеки и их OGG не включаются;
  единственный собственный OGG — `Media/silence.ogg`. Локальный QueueLab
  в релиз не входит. Сохраняй согласованную для выпуска настройку
  `X-Vote-Invite`; форматирование ченджлога её не меняет.

## Обязательный формат ченджлога

Сохраняй ченджлог текущего выпуска в `docs/CURSEFORGE_CHANGELOG.md`.
Используй обычный Markdown строго в следующем порядке:

```markdown
## {version}

### Изменения

- Русский текст первого изменения.
- Русский текст второго изменения.

---

### Changes

- English translation of the first change.
- English translation of the second change.
```

- `{version}` — полная версия из TOC, например `1.4.2-forever`. Заголовок
  начинается с `##`; не добавляй к нему название аддона, слово «Версия» или дату.
- Сначала русский раздел `### Изменения`, затем горизонтальный разделитель
  `---`, затем английский раздел `### Changes`. Сохраняй пустые строки вокруг
  заголовков, списков и разделителя. В самом файле не должно быть ограждения кода,
  HTML-блоков `<details>`, `<summary>` или `<time>` из README.
- Русские пункты бери из согласованного описания выпуска. Английские пункты
  должны соответствовать им по смыслу, количеству и порядку. Не добавляй
  технические подробности, которые пользователь исключил из «Что нового».
- Описывай только изменения TalkingHead Ru. Обновление внешней библиотеки
  обозначай как обновление данных или совместимости нашего аддона; не переноси
  в наш ченджлог её новые записи и возможности. Не выделяй внутренний подбор
  NPC-вариантов CatQuest отдельным пунктом. Новым выбором или настройкой называй
  только реально добавленный пользователю элемент интерфейса.
- Результаты проверок существующего поведения не включай в пользовательский
  ченджлог: в нём нужны изменения выпуска, а не отчёт о тестировании.
- Названия библиотек сохраняй. Если упоминается русская надпись в интерфейсе,
  в английском тексте оставь её точной и при необходимости поясни переводом.
- Записывай только текущий выпуск; пример пользователя с `1.4.0-forever`
  задаёт структуру, а не постоянную версию или список изменений.

## Завершение

Сверь версию ченджлога с TOC и ZIP, а обе языковые части — с согласованными
изменениями. Для одного изменения Markdown достаточно просмотра результата;
полный прогон тестов аддона из-за перевода не требуется.

Выдай полные абсолютные пути к ZIP и `docs/CURSEFORGE_CHANGELOG.md` в текстовых
блоках, чтобы их можно было скопировать. Получай абсолютные пути из текущей
копии репозитория; не закрепляй персональные пути в скилле. Если готовился
только ченджлог и ZIP ещё отсутствует, сообщи это вместо выдуманного пути.

Подготовка файлов сама по себе не включает загрузку на CurseForge, публикацию
на GitHub или развёртывание сайта. Выполняй эти действия, когда они входят
в запрос пользователя; учитывай уже данное разрешение без повторного вопроса.
