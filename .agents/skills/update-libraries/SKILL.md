# Обновление библиотек TalkingHead Ru

Работай из корня текущей копии репозитория TalkingHead Ru, содержащего этот скилл
в `.agents/skills/update-libraries/`.
Прочитай его `BUILD.local.md` и соответствующие разделы `docs/DEVELOPMENT.md`.
Для Wayfarer смотри также `docs/internal/wayfarer-integration.md`.
Команды ниже выполняются из корня проекта. Пути к установленным аддонам берутся
из `config/build.env.local.ps1`, переменная `WOWVOICE_FOREVER_BETA_ADDONS`.

## Определить изменения

- Сверь версии и фактические данные, а не только номер релиза. CatQuest и
  CatQuest_Voices обновляются независимо; обновление ядра может менять NPC без
  изменения аудио. Wayfarer хранит NPC в индексах голосовых пакетов.
- Для WowVoice проверяй обе папки: `WowVoice` и `WowVoiceSounds`, их TOC,
  состав Lua/JSON и фактические OGG. Отличай список записей и длительности от
  текстов квестов и базы NPC. Наш `src/Index.lua` — сохранённый Classic-источник,
  а не свидетельство наличия такого индекса в установленном Forever-аддоне.
  Если появились тексты или NPC, сначала проверь схему и покрытие и добавь
  разбор данных в соответствующий импортёр; резерв первого места WowVoice
  в `import-quest-texts.js` сам по себе ничего из WowVoice не читает.
- При каждом запуске скилла, даже для обновления только одной библиотеки,
  запускай `build.cmd -Task CheckSources` в фоне параллельно с независимым
  локальным аудитом. Forever Quest Pins проверяется через GitHub по
  `Database/ForeverQuests.lua`, независимо от обновлений в CurseForge.
  Перед завершением прочитай результат и проверь дату проверки в
  `artifacts/review/forever-pins-update.json`; не выдавай старый отчёт за новый.
  При `current` достаточно краткой отметки в итоге; при `changed` проверь и
  импортируй обновление по инструкции ниже. `unavailable` не означает актуальность:
  сообщи о неудаче и повтори проверку перед выпуском. Сетевой сбой не мешает
  остальным локальным проверкам.
- Перед импортом сохрани изменяемые метаданные в отдельную папку
  `artifacts/review/`, чтобы сравнить результат. Не редактируй установленные
  сторонние аддоны, их TOC, индексы и звуковые файлы.
- Источники разбираются как данные: не исполняй сторонний Lua. Не подменяй
  проверку файлов одним обновлением поля версии.

## Импортировать затронутые данные

- **WowVoiceSounds:** `node tools/generate-classic-metadata.js <WowVoiceSounds>`;
  сверка без записи: та же команда с `--check`. Читай OGG напрямую из установленной
  библиотеки; сохраняй только `src/Durations.lua`, манифест измерений и историю
  хешей. Источник покрытия — `Durations.lua` из соседней папки установленного
  `WowVoice`; его положительные ключи `<questID><a/p/c>` должны точно совпадать
  с текущими OGG. Для импорта нужны обе папки; в игре основной WowVoice не нужен.
  Числовые длительности измеряются по OGG, а не копируются из таблицы автора.
  Генератор сохраняет версию/TOC и хеш входного индекса и полностью заменяет
  активную таблицу: отсутствующие записи прежнего пакета не восстанавливаются.
  При `Classic coverage mismatch` проверь согласованность обновления обеих папок;
  сохрани списки добавленных, исчезнувших и изменённых по SHA-256 файлов.
  Не обходи проверку и не приписывай новым ID названия, тексты или NPC из имён OGG.
  `src/Index.lua` остаётся справочником названий/говорящих, не источником покрытия.
  История хешей хранит прежние ревизии для аудита, но не делает их доступными.
  При запросе только аудита сохрани отчёт и опиши необходимую адаптацию.
- **CatQuest Voices:** `node tools/import-forever-audio.js <CatQuest_Voices>`.
  Сохраняй также `docs/internal/catquest-text-history.json`: импорт хранит тексты
  по имени файла и SHA-256. Если новый индекс убрал субтитры, прежний текст
  используется только для той же записи с совпавшим хешем. Новые субтитры выше
  истории; изменённые/удалённые записи не наследуют старый текст. Проверяй
  `retainedCatQuestTexts` в манифесте текстов и потери покрытия, а не только
  число аудиофайлов. Историю нельзя пересоздавать из уже обеднённого индекса.
- **CatQuest NPC:** `node tools/import-catquest-speakers.js <CatQuest>`.
  Если изменился только `NpcData.lua`, не требуется перегенерировать аудио.
- **Wayfarer:** после обновления голосовых пакетов выполни все три импорта:
  `node tools/generate-wayfarer-metadata.js <AddOns>`,
  `node tools/import-quest-texts.js <AddOns>`,
  `node tools/import-wayfarer-speakers.js <AddOns>`.
  Последний читает `qg`, `npc` и говорящих `q[id].a/p/c.s`; даёт связи выдачи/сдачи,
  имена и облики. Не заменяй отсутствующего принимающего выдающим NPC и не
  назначай рассказчику NPC. Импорт NPC не требует OGG и может запускаться отдельно.
- **Forever Quest Pins:** при `changed` получи `Database/ForeverQuests.lua` и
  `Database/Metadata.lua` из одного указанного коммита. Запусти
  `node tools/import-forever-pins-speakers.js <Database> <полный-SHA>`.
  Используй только актуальную базу Pins на основе All The Things. Старый снимок
  Wowhead Forever и его импортёр удалены; не возвращай их как резервный источник.

Проверенный 18.10.2026 Forever-комплект: WowVoice **1.1.0**, WowVoiceSounds
**0.1.0**. В основном аддоне `Durations.lua` содержит 9 917 ключей
`<questID><a/p/c>`, точно соответствующих OGG; отдельного `Index.lua`, базы NPC
и полных текстов нет. `WowVoiceSounds.lua` содержит только комментарии;
в Vorbis-комментариях всех записей есть лишь поле `encoder`.
Это метаданные наличия/длительности, не источник субтитров или говорящих.
По сравнению с сохранёнными 10 891 файлами: 1 677 добавлены, 2 651 отсутствуют,
у всех 8 240 общих имён изменился SHA-256. Прежний номер звукового пакета
не подтверждает прежний состав. Изменение хеша само по себе не доказывает
переозвучку: могло измениться кодирование. Эти числа — снимок аудита;
при следующем обновлении заново проверяй установленный комплект.

Повторный выпуск Forever от 19.10.2026 (CurseForge File ID `9251044`) сохранил
версии WowVoice `1.1.0` и WowVoiceSounds `0.1.0`, но изменил SHA-256 7 655 из
9 917 записей без добавлений и удалений. По решению пользователя отображаемая
версия библиотеки остаётся `0.1.0`; не придумывай суффикс версии для интерфейса.
Различай выпуски по хешам и ID публикации, сохраняя историю прежних ревизий.

После импорта CatQuest Voices также выполни `node tools/generate-speakers.js`:
голос `narrator` у описания (`a`) теперь является входом общей базы NPC.
Явный рассказчик сохраняется как `{ narrator = true }` и блокирует NPC из
источников ниже по приоритету. В Wayfarer `a.v = narrator` важнее общего `qg`
того же пакета. Не считай отсутствие `s` или мужской голос признаком рассказчика.
Не переноси признак из `p/c` в описание; принимающий NPC остаётся независимым.
На сайте рассказчик имеет нулевые NPC/облик/модель и пустые расу/пол, поэтому
его голоса не попадают в группу пола/расы принимающего NPC.

Все импорты NPC пересобирают единую `src/Speakers.lua`. В игре нет обхода
отдельных баз по очереди. Источники и решения фиксируются в
`docs/internal/speakers-manifest.json`.

Все библиотеки озвучки остаются внешними. Не копируй их OGG в проект,
`backups`, `artifacts` или релиз. Единственный собственный звуковой файл —
`src/Media/silence.ogg`; для релиза используется только `PackageAddon`.

## Классифицировать NPC перед сборкой каталога

После импорта и дополнения отсутствующих обликов обязательно выполни
[classify-npcs](../classify-npcs/SKILL.md) до итогового экспорта каталога,
подготовки моделей и отгрузки. Передай снимок общей базы до импорта и список
изменённых источников/NPC. Этот этап проверяет новые пропуски категорий,
потерянные и изменившиеся категории, пол и возраст, сохраняет неоднозначные
случаи для ручной проверки и пересобирает общую базу с подтверждёнными правилами.
При получении новых обликов после этого этапа повтори классификацию затронутых NPC.

Правила видов, исключения и примеры поддерживаются только в `classify-npcs`
и его справочнике. Проверь отчёт этапа: что исправлено, какие задания требуют
проверки в игре и какие сравнения сменили категорию. Не выдавай нерешённые
категории за проверенные. Затем продолжай проверки и отгрузку этого скилла
с учётом ограничений пользователя на публикацию.

## История версий аудиофайлов

Все три аудиоимпортёра автоматически дополняют
`docs/internal/audio-recording-history.json`. Сохраняй эту таблицу в Git вместе
с манифестами; не удаляй и не пересоздавай её из текущего снимка. Учёт начинается
с выпусков, проверенных 12.10.2026; прежние версии не достраиваются предположениями.
После импорта выполни `node tools/audio-recording-history.js --check`.
Если манифест обновлён другим инструментом, сначала проверь его против файлов,
затем добавь командой без `--check`. При изменении генератора истории запусти
`node tests/validate-audio-recording-history.js` и тесты затронутых импортёров.

Новая версия определяется SHA-256 файла, даже при прежних размере и длительности.
Пока изменение тегов/кодирования тоже считается новой версией: PCM-сверки нет.
Одинаковый номер пакета с разными файлами сохраняется как неоднозначный, а не
перезаписывается. Полная история остаётся в таблице. Рейтинг рассчитывается
на сайте; аддон использует готовый встроенный или импортированный снимок.
Формат истории и правила описаны в
`docs/internal/audio-recording-history.md`.
Голосование оценивает только описания (`a`), результаты агрегируются
по расе и полу говорящего NPC. Для `p/c` используется предпочтение группы
их собственного говорящего, а не автоматически победитель описания. Не путай
пол NPC с `playerVariant`. Историю веди для всех этапов; групповой выбор не
означает прямую оценку `p/c`. Обновление только `p/c` не сбрасывает оценки описания.

## Каталог сайта и кэш моделей

После импорта изменений, затрагивающих состав сравнений, версии записей, тексты
или NPC сайта голосования, обнови переносимый каталог и дополни кэш моделей.
Выполняй после всех затронутых импортов, чтобы каталог и кэш соответствовали
одному снимку данных. Подробные команды установки инструментов, упаковки
и переноса: [MODEL-CACHE.md](../../../web/voice-vote/MODEL-CACHE.md).
Для облегчённых файлов обязательно прочитай также
[PORTRAIT-PACKS.md](../../../web/voice-vote/PORTRAIT-PACKS.md).

```powershell
node web/voice-vote/export-site.mjs artifacts/voice-vote-deploy/catalogue
node web/voice-vote/prepare-model-cache.mjs
node web/voice-vote/prepare-model-cache.mjs --verify
```

Проверяй код завершения каждого шага до следующего. Используй прежнюю папку
`artifacts/voice-vote-model-cache`: новые `displayID` определяются по каталогу,
готовые зависимости повторно используются. Не очищай кэш при росте базы.
Полный контрольный проход выполняется без `--quest-ids`, с отключённой загрузкой
ресурсов извне. В `verify-report.json` должны быть `completed: true`,
`partial: false`, `ready == total` и пустой `failures`. Частичная проверка трёх
моделей не подтверждает готовность каталога. Задания без известного облика
отдельно перечислены в `unavailableQuestIDs` и используют штатный свиток.

При сбое сохраняй кэш и отчёт, исправляй причину и повторяй подготовку/проверку;
не объявляй комплект сайта готовым при неполном проходе. В итоговом сообщении
укажи число готовых/повторно использованных/ошибочных обликов и путь к отчёту.
Если публикация сайта входит в задачу, сначала перенеси дополненный кэш в
`model_cache`, затем публикуй согласованные каталог и внешние аудиобиблиотеки.
Для подготовленного кэша используй `VOICE_VOTE_MODEL_OFFLINE=true`.
Этот этап не включает OGG в кэш, Git или Docker-образ. Публикация выполняется
по правилам завершающего этапа ниже. Изменение файла на Wowhead под старым URL автоматически не
определяется; намеренное обновление ресурсов делай в отдельной папке по инструкции.

### Обязательно оптимизировать модели перед отгрузкой на сервер

При каждом добавлении или изменении моделей на сервере после подготовки и
проверки исходного кэша обязательно пересобери, проверь и установи производные
файлы. Успешная загрузка исходника и наличие браузерного кэша не заменяют
оптимизацию. Не заканчивай обновление переносом одного `modelviewer/`.
Сохраняй полную геометрию тела, прежние качество, текстуры, ракурс и освещение:
по согласованию с пользователем обрезка по пояс не нужна. Упаковщик удаляет
неиспользуемые вершины других уровней детализации и ключи лишних анимаций,
сохраняя Stand, Talk, их зависимости, общие дорожки и камеры.

```powershell
npm.cmd --prefix web/voice-vote run test:portrait-packs
node web/voice-vote/install-portrait-packs.mjs
```

- Выполняй установку только после успешных проверок. Первая команда сравнивает
  исходные и облегчённые данные реальным парсером просмотрщика, затем проверяет
  позы и материалы в WebGL. Отчёт — `artifacts/portrait-packs/verification.json`:
  `failed` должен быть пустым, `verified` — непустым. Проверь свежесть отчёта.
  Перед установкой нужен проход по всему кэшу без `--ids`: частичный запуск
  перезаписывает этот отчёт и не подтверждает готовность остальных файлов.
- Браузерная проверка по умолчанию охватывает несколько эталонных персонажей,
  а не весь каталог. Новые семейства моделей дополнительно проверь командой
  `node web/voice-vote/tests/portrait-pack-render.mjs --quests=<ID,ID>`;
  для другого каталога передай `--catalogue=<путь к site-catalogue.json>`.
  Проверяются нейтральная поза, девять точек разговора и возврат в нейтральную.
- Разговор может ссылаться на отдельные `.anim`, в том числе дополнительные
  варианты. Если автономная проверка обнаружила недостающий файл, дополни
  исходный кэш этой зависимостью и повтори тест; не отключай проверку и не
  заменяй разговор статичной позой. Эти файлы также перенеси на сервер.
- Проверь каждый элемент `unsupported`, а не только отсутствие `failed`.
  Для добавленных/изменённых файлов перечисли модель, затронутые квесты,
  причину исключения и размер передачи геометрии вместе со скелетом/анимациями.
  Не называй исходный fallback оптимизированным или всю задачу завершённой,
  если нужные модели всё ещё передаются в исходном размере. Исправляй поддержку
  формата с проверкой внешности и анимаций; если это не удалось, явно сообщи
  оставшееся ограничение. Не убирай эффекты и не отключай защитные проверки.
- Отдельные SKID-скелеты без родителя, частицы и ленты поддерживаются упаковщиком.
  Для SKID передавай также производные `portrait-packs-v1/skel/*.skel` и их
  хеши из `verification.json`: одной оптимизации M2 недостаточно. Проверяй
  совместно геометрию и скелет; изменение любого исходника отменяет обе части.
- Установщик повторно проверяет хеши и создаёт
  `artifacts/voice-vote-model-cache/portrait-packs-v1/`. Исходный `modelviewer/`
  не заменяй. Производные M2, отчёты и сам кэш остаются вне Git и Docker-образа;
  в Git хранятся упаковщик, тесты и инструкции.
- До переключения сайта перенеси `portrait-packs-v1/` с `verification.json`
  в тот же том `model_cache`, рядом с дополненным `modelviewer/`. Сервер выдаёт
  проверенные файлы через `/modelviewer/portrait-v1/classicplus/`; при отсутствии
  пакета или несовпадении хешей использует исходник. Это страховка, а не замена
  проверки: после публикации подтверди `portraitPack: true` для поддерживаемой
  модели и готовый портрет через [DIAGNOSTICS.md](../../../web/voice-vote/DIAGNOSTICS.md).
  Для SKID подтверди `portraitPack: true` также у `.skel`. Сверь хеши/размеры
  опубликованных файлов с отчётом. Сохраняй исходный кэш, прежний отчёт и образ
  для отката; неподтверждённый откат к исходнику считай проблемой отгрузки.
- Вместе с ресурсами передай основной `manifest.json`. Проверь годовой кэш
  с SHA-256 в URL по [MODEL-CACHE.md](../../../web/voice-vote/MODEL-CACHE.md):
  изменённый файл получает новый адрес, неизменённые файлы не скачиваются снова.
  Запусти `node web/voice-vote/tests/model-cache-render.mjs --quests=<ID,ID>`
  для затронутых семейств, включая модели с внешним скелетом.

## Автоматически дополнить отсутствующие облики из Wowhead

После импорта библиотек проверяй новые пропуски общей базы. Начинай с NPC,
используемых в голосовании; оставшиеся реальные NPC можно обработать с `--scope all`.

```powershell
python tests/test_wowhead_appearances.py
python tools/fill-wowhead-appearances.py --scope voting --apply
```

Скрипт читает текущий каталог из установленных библиотек, исключает рассказчиков,
отсутствующих NPC и служебные ID от 900000000. Запрашивает русскую страницу Forever
последовательно с паузой; принимает облик только при совпадении точного ID в URL,
canonical и данных View in 3D, а также двух значений displayID на странице.
Имя берётся из заголовка без титула, только если оно русское. Дополнения не
перекрывают существующие записи; генератор сохраняет приоритет библиотек.

HTML, хеши, результаты и резервные копии находятся в `artifacts/wowhead-appearances/`;
в Git попадают только подтверждённые дополнения и пересобранная общая база.
Повторный запуск использует сохранённые ответы; отрицательные результаты живут
семь дней (`--refresh` позволяет повторить их проверку). При 403/429 или трёх
сетевых ошибках подряд проход останавливается. Не обходи блокировку; частичный
отчёт не означает полного успеха. `voting-report.json` / `all-report.json`
содержат `completed`, результаты каждого NPC и реально добавленные ID.

После прохода проверь изменения ролей и имён, тесты генератора и аддона,
затем экспортируй каталог и подготовь/проверь новые облики по процедуре выше.
Наличие displayID на странице ещё не подтверждает работоспособность портрета.
Перед публикацией нужны полный автономный проход и проверка облегчённых моделей;
при отложенном деплое сохрани результаты как ожидающие публикации.


## Приоритеты, согласованные с пользователем

Основной критерий — частота поддержки источника. Порядок фиксирован в
`tools/generate-speakers.js`; номера версий разных проектов не сравниваются.

- Выдающие NPC: CatQuest → Wayfarer → актуальные Pins → Classic.
- Принимающие NPC: CatQuest → Wayfarer → Classic.
- Облики: CatQuest → Wayfarer → подтверждённые дополнения, только по точному ID NPC.
  `docs/internal/npc-appearance-supplements.json` хранит точечные связи NPC–облик
  с URL страницы Forever, датой проверки и основанием. Дополнения заполняют
  только отсутствующий облик, не меняют роли квестодателей и не перекрывают
  библиотеки. Совпадение имени двух NPC само по себе не подтверждает общий облик.
- Имена: предпочитать русские; при равном языке
  CatQuest → Wayfarer → Classic → подтверждённые дополнения.
  При точечном дополнении облика из Wowhead открывай также русскую страницу
  `/forever/ru/npc=<ID>` того же NPC. Если там есть русское имя, сохраняй его
  без титула в `nameRu` записи `npc-appearance-supplements.json`, с русским URL,
  датой и подтверждением в `evidence`. Не переводи имя самостоятельно.
  Генератор заменяет английское или отсутствующее имя подтверждённым русским,
  сохраняя приоритет уже имеющихся русских имён библиотек. Проверь имя в
  `npcs`, связанных `givers`/`finishers` и каталоге сайта после перегенерации;
  не правь только сгенерированный Lua — локализация должна переживать импорт.
- Явные сведения о нескольких/противоречивых квестодателях
  защищены от замены одиночным NPC; отсутствие сведений позволяет следующий источник.
- В игре фактически полученные NPC и облики выше общей базы на любом языке.
  Резервные модели не записываются в наблюдения персонажа. Поздняя загрузка
  реальной модели должна обновлять исходную запись и показанный портрет.
- Приоритет озвучки в настройках не меняет текстовую базу или выбор NPC.
  Порядок текстов остаётся WowVoice → CatQuest → Wayfarer; на ruRU игровой текст
  выше базы, на enUS/enGB русский текст базы выше игрового.

## Проверить результат

При аудите интеграции сохраняй правило обратимого подавления: пока TalkingHead Ru
включён, автоматика и всплывающие сообщения библиотек по умолчанию отключены.
При выключении и `PLAYER_LOGOUT` возвращаются только наши изменения.
Явный выбор пользователя в настройках лора CatQuest (`loreAuto`, `loreMark`) и
Wayfarer (`zoneMode`) имеет приоритет и сохраняется после перезапуска через
`TalkingHeadRuDB.libraryPreferences`. Не сбрасывай эти исключения при обновлении
библиотек; при первом подключении уже включённый лор временно подавляется,
поскольку отличить пользовательский выбор от исходного значения невозможно.
Начиная с CatQuest 0.7.0 проверяй также `world`: это автоматическая озвучка
реплик мира из отдельного CatQuest_World. По умолчанию временно выключай её,
восстанавливай при отключении TalkingHead Ru; явное включение пользователем
сохраняй как исключение через тот же механизм. Сам пакет мира не импортируется
в квестовую базу или голосование.

Запусти `node tools/generate-speakers.js --check` и
`node tools/import-wayfarer-speakers.js <AddOns> --check` для установленных пакетов.
При обновлении WowVoiceSounds выполни
`node tools/generate-classic-metadata.js <WowVoiceSounds> --check`.
Общие тесты проверяют согласованность сохранённых метаданных без библиотек;
сверка реальных OGG выполняется этой отдельной командой по установленной библиотеке.
После всех затронутых импортов CatQuest запусти
`node tools/audit-catquest.js <CatQuest> <CatQuest_Voices>` и
`node tools/check-catquest-compatibility.js <CatQuest_Voices>`.
При изменении аудио Wayfarer используй также
`node tools/check-wayfarer-compatibility.js <AddOns>`.
Проверь изменения количества NPC/связей/обликов, `protectedExclusions`,
`conflicts` и `appearanceConflicts` в отчёте. Конфликты разрешаются согласованным
порядком; отчёт позволяет объяснить выбор, а не требует вручную выбрать каждый NPC.

Для изменений генератора запусти соответствующие тесты импорта; после изменения
общих runtime-данных — `node tests/run.js`, перед выпуском — `build.cmd -Task Test`.
Обнови текущие инструкции и данные версий в документации, не переписывая
исторические отчёты прошлых миграций. Отдельно укажи, что проверено автоматически
и что проверено в игре.

## Завершить обновление: сайт, рейтинг и бета

Перед публикацией проверь актуальные ограничения в `BUILD.local.md`.

По инструкции пользователя от 12.10.2026 обычное обновление библиотек включает
установку проверенного TalkingHead Ru на бету и обновление сайта голосования,
если затронуты его данные. Дополнительное подтверждение этих шагов не нужно.
Явные ограничения текущего запроса («только аудит», «локально», «не публиковать»)
имеют приоритет. Это не включает выпуск нового релиза, тега или публикацию на
CurseForge/GitHub Pages.

- Для сайта сравни каталог, тексты, NPC, версии/хеши записей и настройки камеры
  с опубликованным снимком. Если различий нет, повторный деплой не нужен.
  Текущий хост и порядок переноса описаны в
  [HOSTING.md](../../../web/voice-vote/HOSTING.md) и
  [DOCKER.md](../../../web/voice-vote/DOCKER.md).
- Сначала подготовь и проверь каталог, аудио и кэш моделей. Полный автономный
  проход обязателен; новые ошибки исправь до публикации. Уже документированная
  заглушка для известного проблемного облика может остаться, если нет новых
  сбоев; явно укажи её в отчёте, не называй проход полностью успешным.
- Перед каждой новой версией сайта обязательна проверка предзагрузки аудио:
  `npm.cmd --prefix web/voice-vote run test:audio`. Она также встроена в сборку
  Docker-образа вместе с проверками безопасности облегчённых моделей. Не обходи
  эти проверки при отгрузке; после изменения кэша выполни процедуру упаковки выше.
- Сохрани действующие пути `audio-manifest.json` для неизменённых ID записей.
  Новые файлы передавай напрямую из установленных библиотек на хостинг по
  отдельным путям с хешами; прежние файлы нужны для отката. Не помещай OGG в
  локальные архивы проекта. Дополняй кэш до переключения каталога.
- Перед переключением сохрани согласованную резервную копию SQLite, очереди
  несохранённых голосов и текущего каталога. Сохраняй рабочий том голосов и
  историю хешей; не сбрасывай оценки при обновлении. Если меняются только
  внешние каталоги, используй существующие образы приложений. При изменении
  встроенных `ranking-groups.json` или `ranking-speakers.json` пересобери и
  проверь образ API: замена внешнего каталога не обновляет ресурсы внутри JAR.
- Переключай согласованные файлы каталога вместе и перезапускай нужные сервисы.
  Проверь здоровье, публичный каталог, звук и портреты без отправки тестовых
  голосов в рабочую БД. При ошибке откати каталог/образы, сохранив живую БД
  и поступившие голоса. Не повторяй неудачный деплой без устранения причины.
- Обнови актуальные показатели в README и `docs/CURSEFORGE_DESCRIPTION.md`,
  не меняя исторические релиз-ноты. В итоге перечисли, что импортировано,
  установлено на бету и опубликовано на сайте, а что требует проверки в игре.
- После обновления сайта (либо подтверждения отсутствия различий) обязательно
  обнови встроенный снимок рейтинга сообщества: `build.cmd -Task ExportAddonRanking`,
  затем `node tools/update-addon-ranking.js` и `node tests/validate-ranking.js src`.
  Это входит в обычное обновление библиотек, а не только в выпуск релиза.
  Проверь успешность каждого шага, свежесть `generatedAt`, состав групп и изменение
  `src/BuiltinRanking.lua`. Экспорт должен использовать уже опубликованный каталог,
  чтобы рейтинг соответствовал новым записям и категориям NPC. При ошибке сохрани
  прежний снимок и явно отметь незавершённый этап; не выдавай старый файл за новый.
- После обновления рейтинга и успешных проверок выполни
  `build.cmd -Task DeployAddon -Target ForeverBeta` по `BUILD.local.md`.
  Используй локальный конфиг, сохрани поддерживаемые им отладочные файлы и сверь
  установленную копию с `src`, включая `BuiltinRanking.lua`. Сторонние аддоны
  не изменяй. В итоговом отчёте укажи дату встроенного снимка и число групп.
