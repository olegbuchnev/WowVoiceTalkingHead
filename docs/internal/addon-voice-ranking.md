# Рейтинг библиотек для аддона: алгоритм и обмен данными

Дата: 17 октября 2026 года. Статус: **серверный экспорт опубликован; экран, импорт и применение рейтинга добавлены в аддон для локальной проверки**.

Принятый подход: сервер рассчитывает места по модели выбора Люса; один актуальный
голос человека за задание заменяет предыдущий. Аддон получает готовый порядок
и признак ничьи; внутри ничьей применяется пользовательский порядок библиотек.
Кнопка «Импорт в аддон» открывает экспорт кодированной строки THR1.
Серверный JSON-экспорт и build-таска также доступны. Новый экран открывается
из секции «Выбор озвучки» кнопкой «Озвучка по расе и полу». Импорт THR1 позволяет
обновлять рейтинг без обновления самого аддона. В диалоге сайта выводится строка
для вставки в аддон, без кнопки скачивания открытого JSON.

Алгоритм фиксируется на сервере; название алгоритма и параметры в пользовательский
JSON не входят. Версия формата обмена нужна только для совместимости импорта.
Вес истории 0,5 и штраф за сам выпуск новой версии не применяются.
Согласовано затухание исторических сравнений с коэффициентом `0.98` при получении
новых оценок обновлённых записей; без новых оценок исторический ориентир сохраняется.
Это дополнительное правило к модели Люса, а не свойство самой модели.
Затухание и два слоя реализованы в `RankingHistory`, схема SQLite 4.
Экспортёр, миграция, экспорт строки и импорт в аддоне реализованы.
Сервер использует lambda=1 и описанный ниже формат THR1. Импортёр должен
соблюдать этот контракт; параметры остаются внутренней частью серверной реализации.

## 1. Назначение и согласованные требования

Нужен JSON с полным порядком трёх библиотек для каждого известного сочетания
раса–пол говорящего: первое, второе и третье места. Аддон выбирает первую
установленную библиотеку, в которой есть нужная реплика, затем следующую.

Идентификаторы библиотек в экспорте: `WowVoice`, `CatQuest`, `Wayfarer`.
Внутренние имена аддона: `wowvoice`, `catquest`, `wayfarer` соответственно.
Пакеты Wayfarer объединяются в источник `Wayfarer`.

Обязательные свойства:

- Пользователь выбирает один из двух режимов: «Предпочитаемые библиотеки» или
  «По рейтингу». В режиме рейтинга порядок из настройки «Выбор озвучки»
  применяется только внутри явно переданной сервером ничьей. Он не меняет
  порядок разных оценок и не поднимает резервные источники над оценёнными.
  Переключение сохраняет настройки обоих режимов.
- Выпуск новой версии библиотеки сам по себе не меняет рейтинг.
- Голоса прошлых версий участвуют в оценке предпочтения библиотеки для группы.
  Ограничения «только три последние версии» в рейтинге нет.
- Исторические сравнения теряют вес только при поступлении свежих оценок
  соответствующего обновлённого сравнения: множитель `0.98` за новую оценку.
  Время, число выпусков и число экспортов не уменьшают вес. Без новых оценок
  исторический ориентир сохраняется без срока истечения.
- Повторное голосование человека за то же задание заменяет его прежний голос,
  в том числе после замены записи или состава предложенных библиотек.
- Версии не должны размножать актуальные оценки одного человека за одно задание.
- Новое и обновлённое сравнения с одинаковым числом свежих голосов имеют
  одинаковый приоритет. Отдельного бонуса за обновление нет.
- Сохраняются разнообразие групп в очереди, приоритет лично неоценённых
  сравнений и меньшего числа голосов внутри выбранной группы. Среди лично
  неоценённых сравнений первыми идут группы без единого допустимого голоса.
- Рейтинг группы и число свежих голосов за текущие файлы — разные величины.

## 2. Что именно оценивается

Рейтинг относится к **библиотеке в группе говорящего**, а не к номеру выпуска,
конкретному квесту или конкретному хешу файла. Это соответствует предположению,
что характер озвучки одной библиотеки для расы и пола обычно сохраняется.

На сайте оценивается описание задания, этап `a`. Для `p` и `c` аддон применяет
предпочтение группы NPC, произносящего соответствующую реплику. NPC выдачи
не подменяет NPC сдачи. Такие реплики не считаются непосредственно оценёнными.

Хеши файлов и версии остаются в актуальном голосе: они нужны для проверки
голоса, учёта свежести и аудита. Их изменение не создаёт отдельный рейтинг.
Неизвестная установленная версия не становится проверенной благодаря
групповому рейтингу: экспорт не подтверждает качество её конкретных файлов.

## 3. Группы и метаданные

В экспорт включаются только сочетания, для которых есть хотя бы один NPC
в актуальной общей базе (либо NPC актуального каталога сайта). Поддержка ключа
категории в импортёре сама по себе не создаёт группу. Таблица аддона также
скрывает группы импортированного снимка, отсутствующие в его общей базе NPC;
сам снимок при этом не изменяется. Например, после проверки обликов от
17.10.2026 есть `dragon/male`, но нет `dragon/female`: Халех остаётся
`bloodelf/female`. Группа с NPC, но без оценок, по-прежнему выдаётся с `no_data`.

Ключ обычной группы: `(speakerType="npc", race, sex)`.
`race` и `sex` берутся из общей проверенной базы NPC без самостоятельных выводов
по модели, голосу или полу игрока. Категории детей и существ сохраняются
как отдельные значения, если так определено общей базой.

Список групп строится по всем корректно классифицированным NPC в переданном
снимке общей базы, включая NPC выдачи и сдачи; дополняется корректными группами
каталога голосования. Включаются группы без голосов. Не создаётся искусственное
декартово произведение всех рас и полов.

Для обычной группы нужны непустая раса и пол `male`/`female` по действующему
контракту метаданных. Неизвестные значения не угадываются; такие голоса
исключаются из рейтинга. Для неизвестной группы аддон использует общий
порядок библиотек пользователя из настроек.

Явный рассказчик может иметь отдельную группу
`(speakerType="narrator", race=null, sex=null)`. Для этого нужен явный признак
рассказчика в версионированных метаданных. Нулевой NPC и пустая раса сами по себе
недостаточны: текущий переносимый каталог не позволяет надёжно отличить
рассказчика от неизвестного говорящего. До добавления такого признака
экспорт группы рассказчика не выполняется.

Исторический голос допускается в группу, только если сохранённые NPC,
тип говорящего, раса и пол совпадают с проверенными актуальными метаданными
говорящего для этого задания. Исправление категории не переносит старые
голоса в другую категорию и не оставляет их влиять на прежнюю ошибочную группу.
Изменение только модели или камеры при прежних NPC и группе не исключает голос.
Удаление задания из голосования само по себе не исключает голос, если его
говорящий и группа по-прежнему подтверждаются общей базой. При отсутствии
такого подтверждения голос исключается. Отдельный отчёт с причинами исключений
можно добавить в операторскую диагностику; в текущий экспорт он не входит.

## 4. Хранение актуальных голосов и переголосование

Уникальный ключ актуального голоса:

```text
(visitor_id, quest_id, stage)
```

Для текущего голосования `stage=a`. Идентификатор человека определяется
существующим механизмом посетителя; очистка cookie не позволяет надёжно
распознать того же человека и остаётся ограничением системы.

Одна запись хранит:

- выбранную библиотеку и запись;
- полный предложенный набор библиотек с хешами и пакетами;
- снимок говорящего и его группы;
- точный `comparison_id` для текущего механизма очереди;
- время первого голосования и последнего изменения, идентификатор операции доставки.

Новый допустимый голос атомарно заменяет всю запись с этим ключом.
Если раньше человек выбрал A из A/B/C, а теперь B из A/B, прежний голос
полностью исчезает из рейтинга, включая его прежние отношения с C.
Нельзя оставить прежние отношения с C и одновременно добавить новый голос.

Сетевой повтор доставки одного `submission_id` не добавляет оценку. Повтор
того же выбора для того же набора тоже не становится дополнительным голосом.
Настоящая смена выбора или оценка новых файлов заменяет прежнюю запись.
Очередь должна сохранять порядок принятых изменений одного ключа, чтобы
запоздавшая доставка не вернула старый выбор.

Для рейтинга нужны только актуальные записи. Не требуется хранить отдельный
актуальный голос для каждой версии. База растёт от новых сочетаний
«посетитель–задание», а не от повторных обновлений тех же файлов.
Исторический аудит при необходимости хранится отдельно от рабочей таблицы.
Неограниченное хранение событий доставки, аналитики и старых сравнений также
потребует отдельной политики очистки: компактная таблица голосов не ограничивает
автоматически размер всей базы.

## 5. Модель Люса: один голос — один выбор

Наблюдение содержит победителя `winner` и реально предложенное множество
источников `offered` размером два или три. Выбор A из A/B/C — одно наблюдение,
не два независимых. Порядок B и C неизвестен; ничья между ними не предполагается.
Отсутствующая библиотека не получает поражения; источник в наборе не повторяется.

В каждой группе оцениваются три логарифмические предпочтительности `s_i`:

```text
P(winner=i | offered=S) = exp(s_i) / sum(exp(s_j), j in S)
```

При двух вариантах это модель Брэдли–Терри, при выборе одного из нескольких —
модель выбора Люса (top-1). См. [документацию choix](https://choix.readthedocs.io/en/stable/).
Выбор победителя из тройки нельзя передавать как полное ранжирование тройки.

Свежий голос имеет вес `1`, исторический — сохранённый
эффективный вес `w_v`, уменьшаемый по правилам раздела 5.1.
Для каждой группы сервер минимизирует:

```text
L(s) = sum(w_v * (logsumexp(s_j, j in offered_v) - s_winner_v), по голосам v)
       + lambda / 2 * sum(s_i², по трём библиотекам i)
```

Фиксированный параметр `lambda=1` сдерживает крайние значения
на малой выборке; он не является штрафом за выпуск или дополнительным голосом.
`logsumexp` вычисляется устойчиво, с вычитанием максимума перед экспонентой.
При `lambda>0` функция строго выпуклая, минимум единственен. Начальная точка —
три нуля; критерий сходимости — максимальный модуль компоненты
градиента меньше `1e-8`. Используется метод Ньютона с уменьшением шага,
не более 100 итераций. При несходимости экспорт завершается ошибкой,
предыдущий локальный файл сохраняется.

Одна и та же выборка с теми же эффективными весами даёт одинаковый результат.
После введения затухания веса зависят от последовательности обновлений и принятых
свежих оценок; одних последних выборов без состояния весов для восстановления недостаточно.
Для воспроизводимости вычислений счётчики обходятся в фиксированном порядке.
Вес модели не является простым процентом побед или вероятностью первого места.

А:50, Б:10, В:1 от разных людей — 61 индивидуальная строка без историй рейтинга
по версиям. Их суммарный эффективный вес после затухания может быть меньше 61.
Если 10 и 1 — переголосования людей из первых 50, остаётся 50 актуальных строк.
Обновление без голосов ничего не меняет при прежних метаданных говорящих.
Самих чисел 50/10/1 недостаточно для результата: нужны выбранные источники
и предложенные наборы.

### 5.1. Замещение истории свежими оценками

Единица учёта — сравнение записей для задания и этапа, а не отдельная победившая
запись. Замена файла любого участника, включая проигравшего, делает прежнее
сравнение историческим. Обновление пакета без изменения участвующих файлов
ничего не меняет. Исторический голос ослабляется целиком, независимо от победителя.

Для учёта затухания разделяем задания, этапы, подтверждённые группы говорящего
и предложенные наборы библиотек. Свежая оценка A/B не ослабляет историю A/B/C,
оценка другого задания — историю этого задания. Изменение состава участников
не позволяет смешивать разные предложенные наборы. При смене состава прежние
текущие оценки становятся историческими, но их вес сразу не меняется.

1. При замене участвующего файла текущие оценки переходят в историю с прежним
   весом. Уже исторические оценки сохраняют накопленное затухание.
2. При первой оценке посетителем текущего обновлённого сравнения сначала
   удаляется его прежний голос за задание, если он есть, с его фактическим
   оставшимся весом и из его прежнего набора.
3. Оставшаяся история соответствующего набора умножается на `0.98`.
   Новый голос добавляется с весом `1`.
4. Изменение выбора тем же посетителем в том же текущем сравнении только
   заменяет его выбор; повторного затухания нет. Повтор доставки также ничего
   не меняет. Смена выбора не должна позволять многократно ослаблять историю.
5. Следующее обновление снова переносит текущие оценки в историю. Вес старых
   оценок не восстанавливается до `1`. Без новых оценок ни одно обновление
   не уменьшает суммарный вклад.

Если исходная история имеет вес `H0` и поступило `n` свежих голосов от других
посетителей, её оставшийся вес равен `H0 * 0.98^n`. При переголосованиях сначала
вычитаются прежние вклады этих посетителей, поэтому эта сокращённая формула
без поправок неприменима.

Пример для одного задания и неизменного набора библиотек; каждый голос от
нового посетителя, А/Б/В — ревизии сравнения:

| Событие | Исторический вес | Текущие голоса | Общий вес |
| --- | ---: | ---: | ---: |
| А получила 50 голосов | 0 | 50 | 50 |
| Выпущена Б, голосов ещё нет | 50 | 0 | 50 |
| Б получила 10 голосов | 50 × 0.98^10 ≈ 40.85 | 10 | 50.85 |
| Выпущена В, голосов ещё нет | 40.85 + 10 ≈ 50.85 | 0 | 50.85 |
| В получила 1 голос | (50 × 0.98^10 + 10) × 0.98 ≈ 49.84 | 1 | 50.84 |

Таблица показывает объём свидетельств, а не рейтинг библиотеки. Места по-прежнему
рассчитывает модель Люса по победителям и полным предложенным наборам.
В конкретной группе изменение весов может менять места; гарантируется отсутствие
штрафа за обновление без свежих оценок, а не неизменность мест после голосования.
Очистка cookie не позволяет распознать повторного посетителя: его прежний голос
остаётся в истории и ослабляется вместе с ней при поступлении свежих оценок.

## 6. Пересчёт и компактные агрегаты

### 6.1. Расчёт по взвешенным агрегатам

Источник истины — последние индивидуальные голоса с их эффективными весами
и состоянием текущего сравнения. Агрегаты обновляются в той же транзакции.
Экспорт схемы 4 читает слои агрегатов и пересчитывает все группы; для старых
схем 1–3 сохранено чтение индивидуальных голосов с единичными весами.

Для ускорения достаточно девяти счётчиков `(group, offered_set, winner)`:
три набора из двух библиотек по два победителя и один набор из трёх по три победителя.
В целевой функции вклад одинакового наблюдения умножается на сумму его весов.
Счётчики группы складываются в памяти из постоянной таблицы `ranking_layers`.
Замены голосов учитываются транзакционно; экспорт проверяет совместимость
метаданных каждой строки агрегата с актуальным говорящим.
Индивидуальные строки всё равно нужны
для замены, проверки групп и подсчёта участников/заданий.

HTTP-экспорт кэширует результат на 10 секунд; CLI каждый раз считает заново.
Кэш по отдельной ревизии голосов не используется. Изменения становятся видны
после истечения кэша и сохранения принятых голосов из inbox.

### 6.2. Обязательное компактное хранение для затухания

Храним два слоя агрегатов для каждого задания, этапа, группы говорящего
и предложенного набора: исторический `H` и текущий `C`. Это счётчики по победителям,
а не два итоговых ранга или две оценки отдельного аудиофайла. Предложенный набор
сохраняется: только количества побед каждой библиотеки для модели недостаточно.

- При обновлении: `H := H + C`, `C := 0`, без изменения общего веса.
- При свежем голосе: вычесть прежний вклад посетителя, если он есть;
  затем `H := 0.98 * H`, добавить единицу выбранному победителю в `C`.
- При расчёте: суммировать `H + C` по группам и передать модели взвешенные
  счётчики `(group, offered_set, winner)`. Ранги прошлых выпусков не усреднять.

Рядом остаётся одна индивидуальная запись на `(visitor_id, quest_id, stage)`:
последний выбор, предложенные файлы, метаданные и состояние эффективного веса.
Она нужна для точного удаления прежнего вклада при переголосовании и исключения
несовместимых метаданных. Отдельная строка на каждую прошлую ревизию не нужна.
Два агрегата без индивидуальных записей не обеспечивают правило замены голоса.

Объединение истории и отсутствие копий голосов по ревизиям — обязательное
требование реализации. При неизменных посетителях, заданиях, группах и наборах
библиотек 50 обновлений файлов не должны увеличивать число строк голосов
и агрегатов рейтинга. Старые ревизии не создают отдельные результаты:
их вклад сохраняется в общем историческом слое с уже накопленным затуханием.
Проверка с 50 обновлениями и повторными голосами включена в `RankingHistoryTest`.

В схеме 4 `ranking_layers` хранит по победителю две суммы `historical`/`current`;
ключ пула включает задание, этап, NPC, расу, пол и набор источников. `ranking_state`
хранит одну текущую ревизию и номер поколения на задание. Ревизия определяется
хешами участвующих файлов; версия пакета, модель и камера не меняют её.
В `votes` добавлены вес, слой, поколение, пул, ревизия и маска источников.
При затухании обновляются только исторические голоса нужного пула, кроме
заменяемого голоса; агрегаты задания перестраиваются в той же транзакции.
Промежуточные слои и результаты прошлых поколений не сохраняются.

Состояние затухания должно сохраняться в БД атомарно с голосом. Допустима реализация
через общий счётчик затухания и отметку у голоса вместо массовой перезаписи весов,
но она должна сохранять точный оставшийся вклад при переходе между ревизиями.
Экспорт, перезапуск, повтор inbox и повторная публикация того же каталога
не должны дополнительно ослаблять историю. Порядок принятых операций фиксируется;
оценки устаревшего сравнения не считаются свежими для текущих файлов.

Коэффициент сам по себе не очищает БД: компактность даёт объединение всех прошлых
ревизий в `H` и замена последнего индивидуального голоса. Число посетителей и
заданий всё ещё влияет на размер; аналитика и история каталогов требуют отдельной
политики хранения. Автоматическое удаление малого ненулевого веса не согласовано.
При внедрении существующие голоса получают исходный вес `1`; отсутствующую историю
затухания задним числом не выдумываем. Перед миграцией создаётся SQLite-копия
`votes.sqlite.before-ranking-layers-<uuid>.sqlite`. При запуске сервер сверяет
каталог до обработки inbox; повторная сверка выполняется при сохранении голоса
и обновлении кэша экспорта. Поздний голос по прежним файлам сохраняется в историю
с весом 1 и не вызывает затухания. Повторная доставка отсеивается по `accepted_order`.
Для отката к серверу схемы 3 недостаточно заменить образ: нужна совместимая БД
или отдельная обратная миграция, сохраняющая новые принятые голоса.

## 7. Первое, второе и третье места

1. Источники, предложенные хотя бы в одном допустимом голосе, сортируются
   по убыванию `s_i`.
2. Ключ сортировки оценки: `floor(s_i * 1_000_000 + 0.5)`.
   Совпадение ключей — техническое равенство, не статистический тест.
3. Неоценённые источники добавляются после оценённых с `basis="fallback"`
   в фиксированном порядке. Это резерв, не доказанное поражение.
4. Технический порядок внутри ничьей: `WowVoice, CatQuest, Wayfarer`.
   Сервер отражает его в `rank` для воспроизводимости и передаёт одинаковый
   `tieGroup` равным оценённым источникам. Аддон переупорядочивает только
   участников этой ничьей по настройке пользователя «Выбор озвучки».
5. `rank=1,2,3` уникальны и соответствуют массиву.

`tieGroup` — номер первого места в ничьей: `1` для равенства первых двух или
всех трёх источников, `2` для равенства второго и третьего. Он имеет смысл
только внутри одной группы раса–пол. У одиночной оценки и у `fallback`
значение `null`. Отсутствие данных не считается ничьей: при `no_data` все
`tieGroup=null`. В JSON сохраняется фиксированный резервный порядок для
воспроизводимости экспорта; в аддоне группа без оценок использует порядок пользователя.

Источники соединены в графе, если оба входили в предложенный набор допустимого голоса.
Статусы: `no_data` — голосов нет; `partial` — голоса есть, граф трёх источников
не связан; `ranked` — граф связан. При трёх библиотеках и наборах размером два/три
`partial` означает отсутствие оценок одной библиотеки.

`ranked` не означает уверенности при малой выборке. Отдельная диагностика
устойчивости и числа участников/заданий группы пока не реализована.
Порог «20 голосов» не вводится. Попарные циклы разрешаются общей оптимизацией модели.

## 8. Пользовательский JSON

Файл: `addon-voice-ranking.json`. Сервер выдаёт готовые места. Синтетический пример:

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-10-16T12:00:00Z",
  "groups": [
    {
      "speakerType": "npc",
      "race": "dwarf",
      "sex": "male",
      "status": "ranked",
      "ranking": [
        {"rank": 1, "source": "CatQuest", "basis": "votes", "tieGroup": null},
        {"rank": 2, "source": "WowVoice", "basis": "votes", "tieGroup": 2},
        {"rank": 3, "source": "Wayfarer", "basis": "votes", "tieGroup": 2}
      ]
    }
  ]
}
```

- `schemaVersion` — версия формата импорта, не переключатель алгоритма.
- `generatedAt` — дата снимка UTC, RFC 3339 с суффиксом `Z`.
  Сайт и аддон показывают её в местном часовом поясе пользователя в формате
  `ДД.ММ.ГГГГ, ЧЧ:ММ:СС`. Аддон переводит UTC в Unix-время и форматирует его
  через `date`, учитывая переходы на летнее время на дату снимка. Исходная дата
  в строке, SavedVariables и проверке свежести остаётся в UTC.
- Каждая допустимая группа раздела 3 присутствует ровно один раз, даже без голосов.
  Сортировка: `speakerType`, `race`, `sex` лексикографически; `null` перед строкой.
- В `ranking` ровно три разных источника и места 1, 2, 3 по порядку.
  Каждая запись нового экспорта содержит `rank`, `source`, `basis`, `tieGroup`.
- `tieGroup`: `null` или целое число `1`/`2`. Ненулевой идентификатор встречается
  минимум дважды, только у соседних источников с `basis="votes"`, и равен
  первому `rank` этих источников. Число не сравнивается между группами раса–пол.
  Это дополнительное поле схемы 1: прежний `rank` сохраняет своё значение.
  В старых снимках поле отсутствует; импортёр трактует отсутствие как `null`
  и не пытается восстановить ничью из порядка или `basis`.
- `basis`: `votes` или `fallback`; резервные источники идут после оценённых.
  Для `no_data` все резервные. Для `ranked` все имеют `votes`.
  Для `partial` два источника имеют `votes`, третий — `fallback`.
- Обычный NPC: непустая строка `race`, `sex=male/female`. Явный рассказчик:
  `speakerType=narrator`, `race=null`, `sex=null`.
- В JSON нет посетителей, индивидуальных голосов, адресов, локальных путей,
  названия алгоритма и его параметров.

Операторский отчёт отдельно может содержать веса модели, число голосов,
участников/заданий, счётчики, исключения и хеши входных снимков.
Он не входит в пользовательскую строку.

## 9. Серверный экспорт

1. Прочитать каталог и встроенный в JAR снимок общей базы говорящих.
   Для присутствующих в каталоге заданий его метаданные имеют приоритет.
   Проверить, что каталог не изменился за время чтения базы.
2. Прочитать актуальные голоса в одной транзакции SQLite, включая
   подтверждённые WAL-данные. Ожидающие записи inbox не считать сохранёнными.
3. Для старой схемы сначала логически выбрать последнее голосование каждого
   `(visitor, quest, stage)` по всем версиям, затем проверять метаданные.
   Нельзя воскресить старый голос, если последний не прошёл проверку группы.
   Старый агрегированный `results.json` не содержит данных для устранения повторов.
4. Построить полный список групп, счётчики, рассчитать модель, проверить сходимость,
   определить места и статусы. Некорректные наборы, хеши и отсутствующий
   в наборе победитель прерывают экспорт, а не тихо пропускаются.
5. Проверить JSON, записать временный файл рядом с назначением и атомарно
   заменить готовый. При ошибке сохранить предыдущий снимок.
6. Сформировать строку из тех же байтов JSON. Скачивание файла и копирование
   строки должны отдавать один и тот же снимок.

Экспорт не меняет голоса и не устанавливает рейтинг в аддон автоматически.
Повторный расчёт одного снимка даёт те же места; отличаться может `generatedAt`.
Локальная команда использует только исключённый из Git конфиг/окружение
`TALKINGHEAD_SITE_*` для подключения. Команда: `.\build.cmd -Task ExportAddonRanking`; файл сохраняется в
`artifacts/voice-ranking/addon-voice-ranking.json`. HTTP-экспорт использует кэш на 10 секунд.

## 10. Экспорт строки и импорт в аддоне

API выдаёт строку и JSON. Кнопка «Импорт в аддон» доступна в шапке сайта
рядом со ссылкой на аддон. Пользовательский диалог предназначен для импорта THR1.

1. На сайте открыть «Импорт в аддон», увидеть дату снимка, нажать
   «Скопировать строку». JSON остаётся доступен через API и build-таску.
2. В настройках аддона открыть «Выбор озвучки» → «Озвучка по расе и полу» →
   «Импортировать строку», вставить строку.
3. Аддон проверяет данные, показывает дату и число групп. Успешный импорт
   заменяет предыдущий импортированный снимок целиком и сохраняется в SavedVariables.
   Галочка «Сохранить мой порядок для рас и пола» включена при каждом открытии
   импорта. Если её снять, только успешный импорт удаляет все личные порядки групп
   и применяет актуальный рейтинг. Ошибка, устаревший снимок или отмена ничего
   не сбрасывают. Повторный импорт того же актуального снимка также выполняет
   явно выбранный сброс. Общий порядок библиотек и выбранный режим сохраняются.
4. В режиме «По расе и полу» применяется личный порядок группы, если задан,
   иначе самый свежий рейтинг из встроенного и импортированного снимков.
   Общий порядок из «Выбора озвучки» разрешает только явные ничьи `tieGroup`.
5. Для обновления пользователь повторяет экспорт/импорт. Строка — снимок
   на указанную дату, а не подписка на автоматические обновления.

Технический формат первой версии:

```text
THR1:<base64url компактного JSON UTF-8 без padding>.<sha256 этих байтов JSON>
```

JSON сериализуется без лишних пробелов; SHA-256 — 64 строчных шестнадцатеричных
символа. В первой версии нет сжатия. Контрольная сумма обнаруживает повреждение
при копировании, но не подтверждает происхождение строки.

Пределы экспортёра: 64 КиБ декодированного JSON, 256 групп; превышение вызывает
ошибку без обрезки. Импортёр поддерживает те же пределы. Вставка длинной строки
в реальном клиенте игры остаётся отдельной проверкой перед публичным выпуском.

- Удалить пробельные символы только по краям, проверить префикс и длину,
  Base64url и SHA-256; разобрать JSON и проверить инварианты раздела 8.
  Предельная длина строки для этого лимита — 87452 ASCII-символа.
- Отклонять неподдерживаемую схему, повторные ключи JSON, дубли групп,
  неизвестные источники, неверные типы, статусы, места, основания `basis`
  и группы ничьих `tieGroup`, нарушающие инварианты раздела 8.
- Разбирать только данные: не использовать `loadstring` или выполнение Lua.
- Неизвестную старому аддону категорию расы можно сохранить, но нельзя
  подменять ею известную группу. Она применяется лишь при умении определять этот ключ.
- При любой ошибке действующий импорт не меняется. Частичный импорт запрещён.
- Повторный импорт того же SHA-256 ничего не меняет. Более старый снимок
  отклоняется: дата сравнивается с актуальным снимком, данные не заменяются.
- Сохранить структуру, дату снимка, SHA-256 и время импорта в SavedVariables.
  Пользовательского действия удаления импорта нет. Обновление снимка сохраняет
  выбранный режим и общий порядок библиотек; личные порядки групп сохраняются
  по умолчанию, а их сброс требует снятия галочки на экране импорта.

## 11. Применение готовых мест

Сначала аддон проверяет выбранный пользователем режим:

- «Предпочитаемые библиотеки» — применяет ручной порядок и настройки этого
  режима. Рейтинг не участвует в выборе.
- «По расе и полу» — определяет группу говорящего реплики. Если для неё задан
  личный порядок, применяет его. Иначе перебирает `ranking`
  по `rank=1,2,3`, предварительно упорядочив участников каждого ненулевого
  `tieGroup` по настройке «Выбор озвучки». Источники вне ничьей сохраняют свои
  места. Исключения библиотек из ручного режима не участвуют в выборе.
  Если ручной порядок неполон, отсутствующие в нём участники ничьей добавляются
  после перечисленных в порядке `rank`; при отсутствии настройки сохраняется `rank`.

Используется самый свежий валидный снимок по `generatedAt` среди встроенного
и импортированного; при одинаковой дате выбирается импортированный. Поэтому
обновление аддона может автоматически заменить устаревший импорт более свежим
встроенным рейтингом. Время импорта и версия аддона не определяют свежесть.
При `no_data` без личного порядка группы применяется общий порядок библиотек пользователя.
Если снимка или подходящей группы нет либо группа неизвестна, применяется
тот же общий порядок. Режим остаётся «По расе и полу»; исключения библиотек
из ручного режима не применяются. При отсутствии сохранённого порядка используется
стандартный `WowVoice, CatQuest, Wayfarer`.

Пропускаются неустановленные/не загруженные в игре библиотеки и источники без
нужной реплики или варианта обращения к игроку. Отсутствие первого места не
требует пересчёта: используется второе, затем третье. Если реплики нет нигде —
обычное поведение без озвучки. Настройки интерфейса каждого режима показываются
отдельно; их изменение не меняет сохранённые настройки другого режима.

Пример: CatQuest имеет `rank=1, tieGroup=null`, WowVoice и Wayfarer —
`rank=2/3, tieGroup=2`. Если пользователь поставил Wayfarer раньше WowVoice,
эффективный порядок — CatQuest, Wayfarer, WowVoice. Если CatQuest недоступен,
используется Wayfarer, а при отсутствии нужной записи в нём — WowVoice.
Если оценки WowVoice и Wayfarer различаются, ручной порядок их не переставляет.
Правило реализовано в `src/VoiceRanking.lua`. Обычное воспроизведение, журнал
и очередь используют рейтинг; явное прослушивание выбранной библиотеки остаётся
независимым. Метаданные берутся по NPC текущего/сохранённого контекста; без него —
из соответствующей роли `givers` или `finishers`. Неизвестный реально захваченный
NPC, предмет или объект не подменяется расой статического NPC.

В интерфейсе режимы называются «Мой порядок» и «По расе и полу».
На новой установке и при первом обновлении до версии с этим правилом включается
режим «По расе и полу», даже если раньше был выбран «Мой порядок».
Однократная миграция отмечается `TalkingHeadRuDB.voiceRankingDefaultApplied`.
После неё выбор пользователя сохраняется при перезагрузках и следующих
обновлениях аддона. Общий и личные порядки библиотек, импортированный снимок
сохраняются. Импорт не переключает режим автоматически. Приглашение
к голосованию обычно появляется при первом входе для установленной версии
и содержит подсказку о прослушивании примеров и личном порядке библиотек.
Для технического выпуска 1.4.2-forever автоматический показ отключён полем
`X-Vote-Invite: disabled` во всех TOC: окно не открывается при входе, перезагрузке
и выходе из боя. Ручная команда `/thead vote` доступна. Это настройка выпуска,
не отметка о просмотре в сохранённых данных; при подготовке следующего выпуска
решение о показе принимается заново, удаление поля возвращает обычное поведение.
`TalkingHeadRuDB.voiceSelectionMode` хранит `manual`/`ranking`, `voicePriority`
сохраняет карточки, `voiceRanking` — импортированный JSON, проверенную структуру,
SHA-256 и время импорта. Повреждённый сохранённый импорт заменяется встроенным
снимком только при чтении; исходные сохранённые данные не стираются автоматически.

Встроенный публичный снимок находится в `src/BuiltinRanking.lua`. Обновление:
сначала `build.cmd -Task ExportAddonRanking`, затем `node tools/update-addon-ranking.js`.
Генератор не обращается к базе голосов и не включает персональные данные.
Импортированный снимок можно обновить новой строкой; действия удаления нет.

### Личные порядки и прослушивание

Экран «Озвучка по расе и полу» показывает действующий порядок библиотек
и его происхождение: «По рейтингу», «Ваш порядок», «Нет оценок».
В режиме «Мой порядок» таблица показывает общий порядок и соответствующую
подпись; кнопка «Включить по группам» явно включает применение групп.
Недоступные библиотеки остаются на своих местах и визуально приглушены.

Список NPC-групп берётся из общей базы выдающих и принимающих задания персонажей.
Новая категория доступна для настройки, даже если её ещё нет во встроенном или
импортированном снимке рейтинга. В таком случае показывается «Нет оценок» и
используется общий порядок пользователя, пока он не задаст личный порядок группы
или не получит рейтинг. Локальные строки не изменяют сам снимок и не создают оценки.
NPC без квестовых ролей не добавляют строку; группы только для сдачи сохраняются.

Точечные решения пользователя о категории NPC закрепляются в поле `npcs`
файла `docs/internal/speaker-overrides.json` и имеют приоритет над обновлениями
библиотек и правилами обликов. Сильвана (`10181`) с 19.10.2026 относится к
`scourge/female` без подразделений голоса: выдача `5961`, сдача `95803`.

«Сравнить и настроить» открывает группу. Перетаскивание трёх карточек сохраняет
полный порядок источников в `TalkingHeadRuDB.voiceGroupOrders[groupKey]`,
где ключ — `npc:<race>:<sex>` либо `narrator`. Некорректные сохранённые порядки
игнорируются. В общем ручном режиме групповые настройки не применяются;
редактирование группы само по себе режим не переключает.

«Вернуть по умолчанию» удаляет только настройку этой группы. «Вернуть порядок по
умолчанию» после подтверждения удаляет все групповые настройки. Оба сброса используют
последний актуальный снимок, сохраняют импорт, общий порядок для ничьих и
выбранный режим. Обновление аддона сохраняет групповые настройки; импорт также
сохраняет их, если пользователь явно не снял галочку сохранения.

Примеры берутся из описаний заданий с подтверждённым сочетанием говорящего,
тем же, что используется при предпрослушивании. Если подключены две или три
библиотеки, задание должно иметь минимум две доступные записи. При одной
библиотеке доступно одиночное прослушивание с предложением подключить вторую.
При отсутствии примеров настройка порядка остаётся доступна.

В заголовке страницы группы показано само сочетание («Бес — Мужской»).
В блоке примера выделены название задания и имя NPC; если название не получено
из клиента или сохранённого контекста, используется локальный `WowVoiceIndex`.
Обратный индекс названий готовится порциями в фоновой очереди и сохраняется
в памяти. Круглые кнопки Play используют иконку и цвета библиотек из каталога.
Остановить озвучку можно крестиком говорящей головы.

Первый пример выбирается стабильно: сначала задания с тремя записями, затем
по ID. Кубик случайно выбирает остальные задания без повторений до исчерпания
набора; начало следующего цикла не повторяет предыдущий пример. При менее
двух заданиях кубик отключён. Доступность проверяется через разрешение реальных
путей записей; обновление библиотек инвалидирует набор. Все три кнопки
прослушивания видимы, недоступные отключены с пояснением.

Страница открывается сразу; пока готовятся примеры, в блоке прослушивания
показан спиннер. Карточки порядка и навигация доступны во время загрузки.
Подбор идёт через общую очередь `WV.Work` с мягким суммарным бюджетом
1 мс на кадр, совместно с разогревом портретов. Обход индексов, проверка
говорящих, разрешение записей и сортировка разбиты на небольшие шаги.
Сумки и сохранённые внешности NPC сканируются один раз на весь подбор.
Уход со страницы отменяет задачу; устаревший результат не применяется.
Изменение личного порядка, режима или снимка рейтинга не требует повторного
подбора: `audioCatalogRevision` меняется только при обновлении доступности
аудиоданных, отдельно от общей `audioRevision`.

Прослушивание не отправляет голоса и не меняет предпочтения. При смене примера
и выходе из экрана останавливается только принадлежащий ему предпросмотр;
начавшееся вместо него обычное воспроизведение не прерывается.

Модель не устраняет смещение от набора заданий и активности участников.
Один человек может оценить несколько заданий группы. Наличие трёх мест
не устраняет неопределённость малого числа голосов.

## 12. Очередь и миграция

Очередь продолжает учитывать точный текущий набор файлов. Прежний голос
участвует в рейтинге, но не делает обновлённые файлы уже прослушанными
и не увеличивает свежие счётчики. Новые и обновлённые сравнения равноправны.

Приоритет выдачи:

1. Лично неоценённые сравнения идут перед повторами; принятые ответы в inbox
   текущего посетителя считаются уже оценёнными для очереди.
2. Внутри этого уровня сначала идут известные группы раса–пол без единого
   допустимого сохранённого голоса, затем группы с голосами и неизвестные группы.
3. Среди групп одного уровня сохраняется случайный выбор с мягким снижением
   частоты недавно показанных групп. Число заданий не увеличивает шанс группы.
4. Внутри выбранной группы сначала выдаются сравнения с меньшим числом голосов
   за точный текущий набор файлов.

Отсутствие голосов определяется по всем актуальным голосам группы с проверкой
говорящего и метаданных, как для рейтинга, включая голоса прошлых файлов.
Обновление записей само по себе не превращает оценённую группу в группу без голосов.
После сохранения первого допустимого голоса группа теряет повышенный приоритет
при следующем запросе очереди. Уже выданная клиенту очередь не меняется задним числом.
Группа из JSON без доступных сравнений в действующем каталоге не может попасть
в выдачу; её приоритет применяется после появления таких сравнений.
Бонус за равенство или близость оценок пока не вводится.

Миграция схем 1/2 в SQLite 3 реализована при запуске API. Старый ключ —
`(visitor_id, comparison_id)`; уникальный актуальный ключ — `(visitor_id, quest_id, stage)`.
Порядок перехода:

1. Сделать проверенную копию SQLite и inbox.
2. Для `(visitor_id, quest_id, stage)` оставить последнее голосование по `updated_at`.
   Равные времена разрешать стабильным `comparison_id` по убыванию; это технический
   порядок, а не восстановленная история. Автоматического отчёта о таких ничьих нет.
3. Адаптировать атомарную запись, идемпотентность и порядок доставки.
4. Адаптировать очередь, статистику и ссылки аналитики; проверить голоса,
   принятые до миграции и ещё находящиеся в inbox.
5. Сверить уникальные ключи и пробный экспорт. Старые строки удалять только
   проверенной миграцией с восстановлением из резервной копии.

Для прежних исторических отчётов после миграции нужна архивная копия.
Независимый журнал прослушанных наборов, если понадобится очереди,
не является голосами рейтинга и требует отдельной политики хранения.
Перед переключением production дополнительно сохраняется весь том данных с inbox.
Сам API перед преобразованием непустой старой базы создаёт SQLite-копию
`votes.sqlite.before-active-votes-<uuid>.sqlite` через VACUUM INTO. Миграция
транзакционна. CLI экспорта не запускает миграцию.

## 13. Проверки сервера и импортёра

- Обновления без голосов не меняют места при прежних метаданных.
- Одна актуальная выборка с теми же весами независимо от порядка чтения даёт один результат.
- Переголосование целиком удаляет старый вклад; повтор доставки не добавляет
  голос и не возвращает прежний выбор.
- Тройка даёт одно наблюдение без выдуманного порядка остальных источников.
- 50/10/1 от новых людей дают 61 наблюдение; переголосовавшие не дублируются.
- После внедрения затухания сценарий 50/10/1 из раздела 5.1 даёт общий вес
  около 50.84, сохраняя 61 индивидуальную строку. Повторные обновления без оценок
  не изменяют вес; замена проигравшего тоже переводит сравнение в историю.
- Свежая оценка ослабляет только соответствующую историю; переголосование
  удаляет прежний эффективный вклад. Смена выбора в текущей ревизии, повтор
  доставки, экспорт и перезапуск не вызывают дополнительного затухания.
- Слияние двух слоёв сохраняет веса всех предыдущих ревизий; агрегаты совпадают
  с суммой индивидуальных вкладов после замен голосов и исправлений метаданных.
- 50 обновлений записей и переголосования тех же посетителей за те же задания
  при прежних группах и наборах библиотек не увеличивают число строк голосов
  и агрегатов рейтинга; отдельные результаты прошлых ревизий не накапливаются.
- Расчёт по девяти счётчикам совпадает с расчётом по индивидуальным голосам.
- Исправленные группы исключают несовместимые оценки; рассказчик не смешивается
  с неизвестным NPC.
- Пустая выборка, частичное покрытие, ничьи, циклы и единогласные голоса
  дают конечные значения и воспроизводимые статусы/места.
- Проверить устойчивость предложенного `lambda=1` на реальной малой выборке.
  Техническая ничья не выдаётся за статистическую уверенность.
- Параллельное голосование не нарушает снимок; ошибка не портит предыдущий экспорт.
- JSON → строка → импорт сохраняет все группы, места, основания `basis`,
  признаки ничьих `tieGroup` и дату.
- Повреждённые, обрезанные, слишком длинные строки, дубли и неверные места
  отклоняются до сохранения.
- Проверить большой допустимый снимок, вставку в игре, сохранение после `/reload`,
  повторный импорт и отклонение старого снимка без изменения настроек.
- Отсутствие библиотеки/реплики приводит к следующему месту.
- Изменение общего порядка переставляет участников явной ничьей,
  включая ничью двух оценённых источников при `partial`. Источники вне ничьей
  сохраняют места, а `fallback` остаётся после оценённых источников.
  При `no_data`, неизвестной группе или отсутствии снимка используется общий
  порядок пользователя. Личная настройка группы имеет приоритет над ним.
  Исключения ручного режима не влияют на рейтинг. Старый снимок без `tieGroup`
  сохраняет порядок `rank`. Неверные и одиночные группы ничьих отклоняются.
- Импорт, обновление и удаление рейтинга не меняют выбор в ручном режиме.
  Переключение режимов сохраняет их отдельные настройки.
- Группы без допустимых голосов идут первыми среди лично неоценённых сравнений,
  сохраняя разнообразие групп и не вытесняя новые сравнения личными повторами.
- Старые записи с допустимыми голосами сохраняют покрытие группы после обновления;
  несовместимые голоса после исправления категории не создают ложного покрытия.
