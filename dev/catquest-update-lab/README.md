# Проверка обновления CatQuest до выхода новой версии

Стенд позволяет проверить новую логику на установленном CatQuest Voices 0.5.0.
Версия и индекс меняются только в памяти игры. Файлы CatQuest, OGG и настоящий
журнал заданий не меняются. Стенд хранится вне `src/` и не входит в релиз.

## Установка — один раз

1. Закрой игру. Из корня проекта установи текущий код WowVoice:

   ```powershell
   .\build.cmd -Task DeployAddon -Target ForeverBeta
   ```

2. Подготовь отдельный тестовый аддон:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\prepare-catquest-update-test.ps1
   ```

3. Скопируй папку `artifacts/catquest-update-test/WowVoiceCatQuestUpdateLab`
   целиком в `Interface/AddOns` своей Forever Beta, рядом с `TalkingHeadRu`.
   Внутри неё должны лежать `WowVoiceCatQuestUpdateLab.toc` и `Lab.lua`.
4. Запусти игру. Включи `TalkingHeadRu`, `WowVoiceSounds`, `CatQuest`,
   `CatQuest_Voices` и `WowVoiceCatQuestUpdateLab`. Для этих сценариев нужен
   именно CatQuest Voices 0.5.0, проверенный текущими метаданными WowVoice.
5. В `/thead` включи озвучку, автозапуск и получение заданий. В очереди включи
   «Автовоспроизведение». Закончи или очисти текущую обычную очередь.
   Сохрани исходное состояние настройки звука в фоновом режиме.

## 1. Проверенная версия и только подмена номера версии

1. Выполни `/wvcqupdate reset`, затем `/wvcqupdate status`.
   В чате: версия **0.5.0**, для **98430** — «точный таймер».
   В `/thead` рядом с версией нет предупреждения.
2. Выполни `/wvcqupdate future`.
   В чате: версия **0.6.0**, для **98430** — «приблизительный таймер», **42.150 с**.
   В `/thead` версия жёлтая; подсказка сообщает о непроверенной библиотеке и
   возможной задержке головы и очереди. Выбрана озвучка CatQuest.
3. Выполни `/wvvoices 98430` и нажми **оранжевую** кнопку.
   Запись должна начаться. На женском персонаже она заканчивается примерно
   через **41.94 с**, а таймер — через **42.15 с** плюс обычный хвост плеера.
   Эта задержка ожидаема. На мужском персонаже запись длится примерно **41.53 с**.
4. Пока запись играет, выполни `/wvcqupdate status` и открой `/thead`.
   Звук должен продолжаться, выбранная озвучка — оставаться CatQuest.

## 2. Изменённая запись и новый квест

1. Выполни `/wvcqupdate changed`.
   Стенд подменяет запись **179**: общий файл превращается в варианты пола,
   меняются голос, текст и длительность. Также появляется новый ID **99998**,
   которого нет в наших снимках.
2. Выполни `/wvvoices 179`, нажми оранжевую кнопку.
   Она активна; текст начинается с **[ТЕСТ ОБНОВЛЕНИЯ]**. В чате при
   `/wvcqupdate status` показаны вариант `m` или `f` и таймер **26.450 с**.
   Для этого теста звучит уже установленный OGG квеста 6 — около **23.2 с**.
3. Выполни `/wvvoices 99998`, нажми оранжевую кнопку.
   Новый квест виден в каталоге и воспроизводится; синей кнопки нет.
   Текст начинается с **[ТЕСТ ОБНОВЛЕНИЯ]**, таймер — **20.350 с**.
   Здесь звучит существующая запись квеста 5 — около **20.10 с**.
4. Останови прослушивание крестиком головы. Выполни `/wvcqupdate queue`.
   В очереди должны последовательно сыграть **179 → 99998**. Вступления не
   обрезаются, очередь не зависает; после первой записи допускается задержка.

Если команда очереди сообщает «Включите озвучку, автозапуск, получение заданий
и автовоспроизведение очереди», сценарий ещё не запускался: выключена хотя бы
одна из этих настроек. При уже работающем ручном прослушивании включи три
настройки одной командой и повтори `/wvcqupdate queue`:

```text
/run WowVoice:SetAutoPlayEnabled(true); WowVoice:SetAutoPlayAcceptEnabled(true); WowVoice:SetQueueAutoPlay(true)
```

Команда меняет сохранённые настройки. После теста верни прежние галочки,
если обычно используешь ручное воспроизведение.

Перенаправление на существующие OGG делает только тестовый аддон. Это имитация
новых файлов, а не настоящая новая версия библиотеки. Обычные правила имён
файлов отдельно проверяются автотестами и сверкой установленного пака.

## 3. После нашего обновления возвращаются точные таймеры

1. Выполни `/wvcqupdate audited`.
   Стенд имитирует обновлённые измерения тех же тестовых записей; сама библиотека
   по-прежнему имеет тестовую версию **0.6.0**.
2. В `/thead` предупреждение исчезает, выбор CatQuest сохраняется.
   `/wvcqupdate status` показывает для **179**, **99998**, **98430** «точный таймер».
   У **179** он равен примерно **23.226 с** для мужчины или **23.140 с** для женщины;
   у **99998** — **20.061 с**. Для женского **98430** — **41.945 с**.
3. Повтори `/wvcqupdate queue`. Дополнительной трёхсекундной задержки после
   первой записи быть не должно. Штатный хвост/пауза между репликами остаются.

## 4. Ошибка одной записи не отключает библиотеку

1. Выполни `/wvcqupdate invalid`.
   CatQuest-запись **179** получает некорректную длительность.
2. В `/wvvoices 179` оранжевая кнопка серая, синяя работает.
   Для обычного воспроизведения общий квест использует WowVoice.
3. В `/wvvoices 99998` оранжевая кнопка продолжает работать.
4. Для проверки отсутствующего OGG сначала включи звук в фоновом режиме
   в настройках WoW. Выполни `/wvcqupdate missing`, затем `/wvvoices 99998`
   и нажми оранжевую кнопку. Этот сценарий намеренно обращается к отсутствующему
   `99998.ogg`. При отказе `PlaySoundFile` кнопка станет серой; запись 179
   останется доступной. Выполни `/wvcqupdate changed`: 99998 снова работает.

## 5. Оба режима воспроизведения

Повтори сценарии 1–3 дважды, меняя настройку WoW «Звук в фоновом режиме»
до начала записи. Канал WowVoice оставь «Авто»:

- настройка **включена** — используется `PlaySoundFile`;
- настройка **выключена** — используется `PlayMusic`.

Для непроверенной версии задержка головы и очереди допустима. Обрезание речи,
зависшая очередь и ошибки Lua — сбои. В `PlayMusic` отдельно послушай, не
повторяется ли начало короткого файла до истечения приблизительного таймера.
Повтор подтверждён в режиме `changed` через `PlayMusic`: таймер превышает
длительность файла (подробности ниже). Запиши режим, ID, пол персонажа и время повтора.
После имитации проверки (`audited`) сравни этот же случай с точным таймером.

## 6. Локализация повтора и обрыва через журнал вызовов

После обновления установленного `Lab.lua` выполни `/reload`. Команды ниже
вводятся по одной. Нужны включённые озвучка, автозапуск, получение заданий и
автовоспроизведение очереди, как в установке выше.

1. `/thead channel music`
2. `/wvcqupdate changed`
3. `/wvcqupdate trace`
4. `/wvcqupdate queue`

Оставайся в игре, ничего не переключай до завершения обеих записей (около
50 секунд). Журнал `TRACE` показывает вызовы `PlayMusic`/`StopMusic`, начало
каждой тестовой записи (`START`) и остановку (`STOP`, время от её запуска и
причину). `timer` — длительность из резолвера, `tail` — добавка плеера,
`OGG` — измеренная длительность фактического файла, на который указывает стенд.
Это время вызовов программы, а не доказательство слышимого окончания речи.
Диагностика не меняет таймеры и способ воспроизведения.

Сохрани строки `TRACE` из чата; `/wvcqupdate report` повторно выводит последние
100 строк. При необходимости `/wvcqupdate mark` ставит отметку в момент
услышанного обрыва, но команда не обязательна.

Затем сравни вторую запись отдельно, с тем же приблизительным таймером:

1. `/wvcqupdate trace` — начинает новый журнал; сначала сохрани предыдущий.
2. `/wvcqupdate solo` — запускает только 99998 тем же механизмом очереди.

Запись длится около 20.061 с. Последние слова основной речи: «делает превосходные
тёмные пирожки с крабами». Отметь, дошла ли речь до этих слов в очереди и отдельно,
слышалось ли затем повторное начало. Остановка около `20.350 + tail` означает,
что таймер отработал ожидаемо; более ранний обрыв звука требует дальнейшей
проверки клиента и вызовов, заменяющих музыку.

`/wvcqupdate traceoff` отключает перехват вызовов, сохраняя журнал в памяти.
`reset` и выход/перезагрузка тоже отключают диагностику. После `/reload`
журнал теряется. `solo` не заменяет обычную очередь и допускается только в
режимах `changed` и `audited`.

## 7. Проверка однократного воспроизведения без включения музыки игры

Игровой отчёт 02.10.2026 подтвердил повтор начала обеих записей в `changed`:
для женского 179 файл длится 23.140 с, остановка — через 26.500 с;
для 99998 файл длится 20.061 с, остановка — через 20.403 с в очереди
и 20.401 с отдельно. Повторных вызовов запуска этих OGG в TRACE нет.
Это согласуется с зацикливанием `PlayMusic` до приблизительного таймера;
обрывается уже повторное начало. Эти логи относятся к `changed`, не к `audited`.

Эксперимент `oneshot` заменяет запуск только тестовой очереди на
`PlaySoundFile(path, "Music")` и останавливает полученный handle через `StopSound`.
Игровая проверка сборки 20261002-2 подтвердила отсутствие повторов у обеих
записей и ожидаемое ожидание головы до таймера. Но вместе с голосом стала
слышна музыка игры: этот путь временно включает Music и поднимает его громкость.
В отчёте `background=1`; поведение при отключённом фоновом звуке не проверено.
Пользователь предпочитает сохранить выключенную/тихую музыку игры.

Начиная со сборки 20261002-3, `test` использует штатный автоматический выбор:

- Фоновый звук включён: `PlaySoundFile(path, "Master")`, без изменения
  `Sound_EnableMusic`/`Sound_MusicVolume` и без `PlayMusic`/`StopMusic`.
- Фоновый звук выключен: прежний `PlayMusic`, заменяющий музыку локации голосом.
  Для него ранее проверены заглушение при сворачивании и продолжение с текущего
  места после возврата: воспроизведение в фоне не ставится на паузу.

Приблизительные таймеры головы и очереди сохраняются. В ветке `PlayMusic`
возможный повтор начала до приблизительного таймера остаётся известным
ограничением. Основной плеер не изменён; музыкальный эксперимент в него не
переносился. Приоритет — прежнее поведение при сворачивании и отсутствие
нежелательной музыки игры.

02.10.2026 пользователь согласовал это поведение как итоговое. Последний отчёт
`test solo`, сборка 20261002-3: `background=0`, `oneshot=false`, один запуск
5.ogg через PlayMusic, остановка через 20.404 с при длине файла 20.061 с.
Отдельно пользователь сообщил об отсутствии зацикливания при проверке с фоновым
звуком. Возможный повтор PlayMusic принят как ограничение приблизительных
метаданных, а не отмечен устранённым. Несовпадение версий само по себе не должно
отключать пригодные записи CatQuest.

После обновления `Lab.lua` выполни `/reload`. Оставь свои обычные настройки
музыки и фонового звука. Запусти одной командой:

```text
/wvcqupdate test
```

Команда сама выбирает `changed`, временно выбирает канал `auto`, начинает TRACE
и запускает очередь. В чате должны сразу появиться `build=20261002-3`,
`oneshot=false` и состояние `background`. При `background=1` последуют
`PlaySoundFile channel=Master` и `PlaySoundFile RESULT ok=true handle=...`;
при `background=0` — `PlayMusic`. `oneshot=false` означает, что экспериментальный
перехват Music выключен; штатный Master играет однократно.
Если команда выводит справку без `test`, загружена старая версия стенда.

Первый проход с включённым фоновым звуком: оставайся в игре до конца обеих
записей. Ожидаем один полный проход каждого OGG, затем тишину до прежнего таймера.
В TRACE должны быть
`PlaySoundFile channel=Master` и `StopSound handle=...`, без вызовов `PlayMusic`.
Музыка игры должна остаться выключенной или на своей прежней тихой громкости.
Строка запуска содержит её настройки `musicEnabled` и `musicVolume`.
Сохрани `/wvcqupdate report`.

Второй проход: выключи фоновый звук, затем `/wvcqupdate test solo`.
Примерно через 5 секунд сверни игру на 3–5 секунд и вернись до конца записи.
В TRACE должно быть `background=0` и `PlayMusic`. В свёрнутом состоянии голос
не должен быть слышен; после возврата должен продолжиться с текущего места,
учитывая прошедшее в фоне время. Принудительный Master здесь не используется.
Сохрани `/wvcqupdate report`.

Прежняя команда `oneshot` оставлена только для отдельного сравнения Music;
обычный `test` её не включает.
Завершение: `/wvcqupdate reset`. Команда восстанавливает канал, сохранённый при
запуске `test`, если он не был изменён вручную. После завершения верни свою
настройку фонового звука и `/thead channel auto` для обычного автоматического выбора.

`report` всегда выводит номер сборки, текущий режим, состояние `oneshot`/TRACE
и число строк. При пустом журнале он объясняет, что запуск нужен заново.
Журнал живёт до `/reload` или выхода, поэтому отчёт сохрани до перезагрузки.
Обычные `queue`/`solo` тоже автоматически включают TRACE, если он выключен.

## Завершение и отчёт

Выполни `/wvcqupdate reset`: восстанавливаются индекс, метаданные и исходный выбор
озвучки, удаляется тестовая очередь. Проверь `/wvcqupdate status`: версия **0.5.0**,
нет записи **99998**. Возврати свою настройку звука в фоновом режиме.

При `/reload` или выходе из игры стенд также сбрасывает подмены. Повторно включать
сценарий нужно вручную. Для удаления закрой игру и удали только папку
`WowVoiceCatQuestUpdateLab` из `Interface/AddOns`.

Удобный формат результата:

| Сценарий | Пол | Фоновый звук вкл./выкл. | Звук, голова и очередь | Повтор начала / ошибка |
| --- | --- | --- | --- | --- |
| future, 98430 | | | | |
| changed, 179 → 99998 | | | | |
| audited, 179 → 99998 | | | | |
| invalid / missing | | | | |

## Вариант с настоящей подменой TOC

Можно использовать текущий или старый пак и вручную повысить его версию.
Для этого закрой игру, сохрани копию `CatQuest_Voices.toc` вне папки аддона,
замени только `## Version: ...` на `## Version: 0.6.0` и запусти игру.
Стенд при этом отключи. После теста закрой игру и восстанови TOC из копии.
При замене целого пака сохрани всю предыдущую папку, включая индекс и OGG;
не смешивай индекс одной версии с файлами другой.

Такая подмена проверяет непроверенный режим и реальные файлы старой библиотеки.
Она сама по себе не создаёт новых квестов или изменений формата. Для этих случаев
используй сценарий `changed` выше. Старый пак также требует совместимого CatQuest.

## Проверка OGG без игры

Команда ниже читает установленный пак, имитируя версию **0.6.0**, и измеряет
каждый используемый OGG. Файлы игры и наши метаданные не меняются:

```powershell
node tools/check-catquest-compatibility.js "C:\Games\World of Warcraft\_classic_beta_\Interface\AddOns\CatQuest_Voices" --version 0.6.0 --output artifacts/review/catquest-simulated-future.json
```

В отчёте `missingFiles`, `invalidFiles`, `tooShortTimers` должны быть пустыми;
`maxTimerDelay` показывает наибольшую задержку таймера относительно конкретного
OGG. Для Voices 0.5.0 это мужская запись 1166: около **4.79 с**.
Непроверенный таймер содержит запас **0.25 с**: в старом паке 0.2.0 запись 132
длиннее `d` на **0.181 с**, поэтому одного запаса на округление 0.1 с недостаточно.
В непроверенном режиме ожидаемо отсутствует восстановление JSON-only сдачи
16: её нет в загружаемом Lua-индексе. Это не отказ всей библиотеки.

Чтобы воспроизвести уже случившееся обновление 0.2.2 → 0.3.0, оставь библиотеку
0.3.0 и добавь `--snapshot artifacts/review/catquest-before-0.3.0` с локальными
старыми метаданными. Это проверяет новый код на настоящих изменённых данных
без импорта и без изменения установленного аддона.
